# Данные мобов

`mobs.json` — один источник правды для чисел мобов первого среза: базовые характеристики, атаки с тиками фаз, приёмы без урона, параметры поведения, добыча и волны тестового ивента. Числа взяты из [04-bestiary.md](../docs/design/04-bestiary.md) и гипотез Г6, Г7 из [03-hypotheses.md](../docs/design/03-hypotheses.md). Это гипотезы до плейтестов.

Кто читает файл:

| Кто | Что берёт |
| --- | --- |
| `assets/models/build.py` | тики атак: сборка падает, если метки клипа не совпали с ними |
| витрина `docs/showcase/` | всё: карточки бестиария, таблицы, шкалу фаз |
| сервер мода (`mod/`) | всё: статы, атаки по тикам, параметры поведения, волны; копия вкомпилирована, `/sc reload` перечитывает `config/soulscraft/mobs.json` |
| другие моды (турели RustCraft) | `turret_effects`, `effects`: копия в контент-моде `horizon-mods/soulscraft/data/soulscraft/mobs.json` |

Время везде в тиках, 20 тиков в секунду.

## Моб

| Поле | Что это |
| --- | --- |
| `id` | короткий id, имя файлов модели: `revenant` |
| `key` | id сущности в игре: `soulscraft:revenant` |
| `name` | имя по-русски |
| `env` | среда: `land`, `air`, `water`, `land_water` |
| `role`, `spawn`, `question`, `look` | роль, где живёт, вопрос игроку, образ — текст из бестиария |
| `elite` | элитный моб (громила): книга охотника открывает запись быстрее, у головы свой шанс |
| `tier_p` | ступень силы игрока P, с которой моб появляется |
| `wave_role` | роль в волне ивента (06-altar.md, «Оборона алтаря»): `assault` идёт на алтарь, `hunter` охотится на игроков, `ranged` бьёт издали |
| `undead` | обязательное, `true` или `false` (раунд 11). Нежить — латник, арбалетчик, громила, сорокопут: в тегах `#minecraft:undead` и `#minecraft:inverted_healing_and_harm` контент-мода (пишет `mod/sync.ps1`), яд и регенерация на неё не действуют, мгновенный урон лечит, мгновенное лечение ранит. Остальные (ловчий, удильщик, топяная слизь) — живые: хук `register_goals` снимает с их типа флаг нежити шаблона зомби. Список в хуке держит равным данным тест крейта `the_goal_hook_undead_matches_the_data` |
| `turret_effects` | эффекты модулей турелей RustCraft: id эффекта → множитель длительности, 0 — иммунитет, нет ключа — 1. У нежити `poison` обязан быть 0 (иначе файл не читается). Элитный громила вдвое короче держит кровотечение и замедление |
| `height_px`, `length_px`, `wingspan_px` | размеры модели в пикселях |
| `stats` | `health`, `damage`, `armor`, `speed`, `knockback_resistance`, флаги `flying`, `water_only`. **Когда меняется `stats.health`, сообщить сессии PCT новые числа: таблица здоровья в `tree.json` PCT повторяет их** (опыт за убийство PCT считает от неё; у слизи — здоровье полного размера 4, 16) |
| `hitbox` | своя рамка столкновений в блоках: `width` (по x и z), `height` (от ног), `eye` (высота глаз). Правило — «Рамка столкновений» ниже |
| `damage_note` | пояснение к урону, если он не обычный удар |
| `sizes` | только у слизи: здоровье и урон по размерам. `jump_velocity` — скорость прыжка вверх, `decide_mult` — во сколько раз реже размер принимает решения. Метка опыта `pct.xpNNN` у меньшей слизи умножена на долю размера `(размер / полный)²`: размер 4 × 1, 2 × 1/4, 1 × 1/16, вместе с надбавкой за P, округлено, 1..500 (просьба PCT, 13.11; `scale::size_share`). Дети деления получают свою метку при появлении |
| `attacks` | атаки, см. ниже |
| `moves` | приёмы без урона: блок, кружение, отскок; `clip` — имя клипа |
| `passives` | постоянные свойства: ярость, прилипание, деление |
| `params` | числа поведения (радиусы в блоках, ожидание в тиках, пороги здоровья в долях) |
| `behavior` | поведение текстом из бестиария |
| `notes` | заметки для модели и кода |
| `loot` | добыча-декорация: `item`, `name`, `chance` (доля, 0,04 = 4%). Это же — части брони, которые даёт победа в ивенте (`trophies.json` `drops.armor`) |
| `kin` | обязательное: группы знамён рода (`undead`, `beasts`, `slimes`, `flyers`, `water`). `undead` стоит ровно у мобов с `undead: true` (сорокопут тоже), иначе файл не читается. Остальное — предложение итерации 3: ловчий и удильщик — звери, слизь — слизни и водные, сорокопут — летучие, удильщик — водные |
| `assumed` | пути полей, которые помечены в бестиарии как предположение или добавлены здесь |

## Рамка столкновений: `hitbox`

Решение автора (раунд 8): у каждого моба своя рамка по модели, а не зомби (0,6 × 1,95). Числа взяты из позы покоя рига (`assets/rigs/<моб>.rig.json`), их печатает `cargo test print_rig_bounds -- --ignored --nocapture` в `mod/soulscraft/rules`. Рамка в Minecraft квадратная и не поворачивается с мобом, поэтому длина тела в ширину не идёт, как у ванильных дельфина и фантома.

| Число | Правило |
| --- | --- |
| `width` | самая широкая поперёк (по x) часть туловища: тело, голова, ноги; без рук, щитов, оружия, крыльев, плавников, хвостов. Летуну — треть размаха крыльев, как у ванильного фантома. Вверх до 0,05 |
| `height` | верх модели в покое без тонких частей (уже 0,2 блока: стебель приманки, гребень). Обычному сухопутному мобу не выше 1,95, чтобы он проходил дверь 1 × 2 |
| `eye` | середина головы по высоте (у безголовых — середина тела), ниже верха рамки |

| Моб | Риг: верх, ширина | Рамка | Глаза | Что из этого следует |
| --- | --- | --- | --- | --- |
| латник | 2,13; тело 0,59 | 0,6 × 1,95 | 1,8 | как у зомби: верх шлема с гребнем выше рамки на 0,18 |
| ловчий | 2,12; тело 0,59 | 0,6 × 1,95 | 1,6 | как у зомби |
| арбалетчик | 2,19; голова 0,63 | 0,65 × 1,95 | 1,8 | шире зомби на 0,05 |
| громила | 3,19; тело с наплечником 1,58 | 1,6 × 3,2 | 2,65 | шире 1 блока: путь ищет проходы 2 × 2 и высотой 4 блока (`mobs/path.rs:430-432`), в дверь 1 × 2 не проходит — так задумано для элиты |
| сорокопут | 0,88; размах 1,5 | 0,5 × 0,9 | 0,7 | как ванильная летучая мышь; летит по скорости, не по пути |
| удильщик | 1,0 (стебель приманки до 1,43 — тонкий); тело 0,75 | 0,75 × 1,0 | 0,6 | плывёт по скорости |
| болотная слизь, размер 4 | 0,75; верх 0,55 | 0,55 × 0,75 | 0,5 | размеры 2 и 1 — ½ и ¼ рамки |

Где рамка ставится: хук `register_goals` (`mod/soulscraft/hook_register_goals.rs`) задаёт её каждому новому мобу на сервере и у клиентов; там своя таблица, потому что этот хук компилируется без крейта `rules`, а тест крейта `the_goal_hook_boxes_match_the_data` держит таблицу равной этому файлу. Сервер ставит рамку ещё раз при `/sc reload` и маленькой слизи по её размеру. Ограничение: у клиента меньшая слизь получает рамку размера 4 (клиенту размер приходит только заметкой, а хука с изменяемым мобом у клиента нет).

Тест `hitboxes_follow_the_rigs` проверяет правило по ригам: после смены рига (локоть громилы) он покажет, если рамка перестала совпадать.

## Сила игрока: `power`

Гипотеза Г1 ([03-hypotheses.md](../docs/design/03-hypotheses.md)): `P = tree_share · T + (1 − tree_share) · G`.

| Поле | Что это |
| --- | --- |
| `tree_share` | доля дерева Path-of-craft-tree в P (0,5) |
| `tree_top_branches` | сколько лучших боевых веток из трёх (ближний бой, стрельба, защита) усредняется в `T` (2) |
| `level_weight`, `rank_weight` | вес уровня ветки и её рангов внутри ветки (0,5 и 0,5) |
| `rank_full` | ранги считаются полными на этой доле того, что покупают свои уровни ветки (очко за уровень): доля рангов = ранги / (`rank_full` · min(макс. уровень, всего рангов)) |
| `armor_weight`, `armor_full` | вес брони в `G` и сколько очков брони — полная (0,6 и 20) |
| `weapon_weight`, `weapon_full` | вес оружия в `G` и полная ступень (0,4 и 5, незерит) |

Ветка дерева = `level_weight · уровень/макс + rank_weight · доля рангов` (веса делятся на их сумму; если в сводке нет `ranks`, только уровень). Сводку пишет PCT в данных игрока под ключом `pct:summary` (формат — [integration.md](../docs/research/integration.md), 3.1). Без сводки `T = 0`: сила только по снаряжению, не выше `1 − tree_share`.
## Атака

Атака идёт фазами подряд: замах, пауза, удар, восстановление.

```text
тик 0         windup         windup+hold        +hit             +recover
│── замах ──────│── пауза ──────│── удар ──│── окно игрока ──│ конец
метки:  windup   hold            hit        recover           end
```

| Поле | Что это |
| --- | --- |
| `id`, `name` | id и имя атаки |
| `clip` | имя клипа анимации, метки которого сверяются с тиками |
| `windup` | замах, тиков |
| `hold` | пауза на вершине замаха у задержанной атаки, иначе 0 |
| `hit` | длина фазы удара, тиков: кадр контакта и доводка |
| `recover` | окно игрока после удара, тиков; у прыжка слизи — после приземления: фаза `hit` длится весь полёт |
| `damage` | множитель к `stats.damage` |
| `tell` | что видно во время замаха |
| `knockback` | отбрасывает |
| `effects` | эффекты: `id`, `seconds`, `level` |
| `strikes_at` | тики ударов внутри фазы `hit`, если ударов несколько |
| `dash_blocks` | длина броска; тогда `hit` — время броска |
| `wave`, `arc_degrees`, `projectile` | волна по земле, дуга удара, снаряд. У волны `radius_blocks`, `damage`, `effects` (их получает и тот, в кого попал сам удар), `jumpable` (не задевает того, чьи ноги выше земли больше чем на 0,5 блока) и `impact_ahead_blocks` (центр в стольких блоках перед мобом, у громилы — где падает молот) |
| `cue` | звук и частицы замаха, та же схема, что у ванильных приёмов (`attacks.*.cue` ниже); и `on`: фаза, в которую он звучит (`windup` по умолчанию, `hit`, `recover`) |
| `recover_if` | условие окна: у тарана громилы `wall`, окно 40 тиков только при ударе о стену |
| `window_note` | окно игрока словами из бестиария |
| `follows`, `grab_max_ticks`, `break_hits`, `pulls_down` | хватка удильщика: состояние после броска, а не атака с фазами (все тики 0). Клип хватки идёт по кругу, один круг — `grab_max_ticks`: сборка проверяет его длину. Начинается, когда бросок попал; цель каждый тик ставится в `mouth_ahead_blocks` перед пастью, при `pulls_down` удильщик тянет её вниз на `pull_down_per_tick` за тик; укус — `damage` раз в `grab_hit_every_ticks`; `break_hits` ударов по удильщику или конец `grab_max_ticks` отпускают цель, и он уходит |

Метки клипа считаются так: `windup` = 0, `hold` = `windup` (только если `hold` > 0), `hit` = `windup + hold`, `recover` = `hit + hit`, `end` = `recover + recover`. На кадре `hit` поза контакта.

**`hit` = 2 тика у всех атак (у бросков 6–8 тиков, у двойного взмаха ловчего 4) — наше предположение.** В бестиарии длины фазы удара нет, она нужна анимации и серверу. Поле отмечено в `assumed` как `attacks.*.hit`.

## Открытые вопросы

- **Падение сорокопута в пике.** У атаки `dive` фазы как у всех: замах 14, удар 2, окно 30 тиков. Отдельной фазы для самого падения нет: в клипе птица складывает крылья в конце замаха, а удар на тике `hit` — это касание земли. Сколько тиков птица падает с 8–9 блоков и как сервер растягивает это время (держит клип `dive`, пока она не долетит, или падение входит в 2 тика удара), не решено. `hit` = 2 здесь — то же предположение, что у всех атак, не решение.

## Ванильные мобы: `vanilla`

Утверждённая таблица [07-vanilla-mobs.md](../docs/design/07-vanilla-mobs.md): одиннадцать строк, девятнадцать типов. Код — `soulscraft_rules::vanilla` (разбор, проверки, мозг) и `mod/soulscraft/vanilla.rs` (сервер). Ванильный моб остаётся со своей моделью, целями и выбором цели; мозг SoulsCraft берёт его только на время приёма и коротких режимов (отход, пауза, путь на высоту или в укрытие). Итоги — [p8-vanilla.md](../prototypes/p8-vanilla.md).

| Поле | Что это |
| --- | --- |
| `spawner_radius_blocks` | моб, появившийся в стольких блоках от спавнера (и 2 блока вверх или вниз), — моб из спавнера: растёт по Г2, приёмов нет (Г4), метка `soulscraft.spawner` |
| `groups` | строки таблицы, ниже |
| `untouched` | ванильные мобы, которых дизайн не трогает: крипер (правило автора), уже подходящие, нейтральные, боссы. Тип из этого списка в группе — ошибка чтения файла, крипер — тоже |

Группа:

| Поле | Что это |
| --- | --- |
| `id`, `name` | id строки и её название |
| `types` | типы ванили, `minecraft:zombie`. Тип не может стоять в двух группах |
| `behavior` | как мозг ведёт группу: `brawler` (зомби), `archer` (скелеты), `pouncer` (пауки), `witch`, `crossbow` (разбойник), `axe` (поборник), `heavy` (брут), `ram` (хоглин, зоглин), `fencer` (иссушённый скелет), `cube` (слизни), `phantom`. Каждому, кроме `archer`, нужна своя атака (`lunge`, `pounce`, …), иначе файл не читается |
| `undead` | какие из типов — нежить ванили. Флаги не меняются (раунд 11: ванильная нежить остаётся нежитью), список документирует это и проверяется: только типы группы |
| `wave_role` | роль в волне ивента (`assault`, `hunter`, `ranged`): тип ванили в `events.*.waves` получает её вместо `assault` |
| `attacks` | приёмы на том же автомате фаз, что у мобов SoulsCraft (раздел «Атака»): `windup`, `hold`, `hit`, `recover`, `damage` (множитель к ванильному удару моба), `dash_blocks`, `strikes_at`, `projectile` (`trident`, `potion`, `bolt`), `wave.radius_blocks` (приземление куба), `recover_if: "miss"` (окно `recover` только после промаха, после попадания — `params.recover_on_hit_ticks`). `clip` не нужен: модель ванильная. `only` — приём только у этих типов (трезубец — утопленник) |
| `attacks.*.cue` | как замах виден и слышен без рига: `sound` (`{name}` — путь типа: `minecraft:entity.{name}.angry` у хоглина и зоглина свой), `pitch`, `particle` (частицы вокруг ног), `pose: "aggressive"` (ванильная поза атаки: руки зомби вперёд, трезубец утопленника над головой, топор поборника), `hop` (подскок куба: при приземлении ванильный клиент сам сжимает его), `by_type` — своё для одного типа (пламя магмового куба) |
| `params` | числа поведения, предложения этого среза. Шансы приёмов (`lunge_chance`, `ram_chance`, …) бросаются на тиках решения Г8 (`20 − 10·P`) |

Рост по Г2 у ванильного моба идёт от его собственной базы (здоровье слизи — размер², скорость ребёнка — своя) модификаторами атрибутов `soulscraft:power`, броня — от брони типа. Метка опыта PCT `pct.xpNNN` считается от ванильного здоровья: PCT платит ванильному виду по своей таблице и умножает на метку. Здоровье ванильных видов в данных не меняется, поэтому таблицу PCT править не нужно.

В книге охотника у строки `vanilla.groups` нет своих `stats`: числа каждого её типа (здоровье, урон, броня) страница берёт у движка (`MobType` типа, `soulscraft_book::engine_stats`), а куба — по размеру, как ванильный `setSize` (размер², урон размер, у магмового куба урон + 2 и броня размер × 3). Рост по силе P показывается так же, как у мобов SoulsCraft. Название строки через запятую — названия её типов по порядку (`name` «Зомби, кадавр, утопленник, зомби-житель» для четырёх `types`).

## Ивент

| Поле | Что это |
| --- | --- |
| `id`, `name`, `source` | id, имя, откуда числа |
| `rest_seconds` | передышка между волнами, от и до |
| `defense` | числа обороны алтаря (гипотеза Г12): перехват и возврат, вытягивание, потолок урона по алтарю, проклятие, пролом (`breach`, ниже) |
| `altar_health` | здоровье алтаря до знамени стойкости |
| `tier` | ступень ивента: нужен алтарь не ниже этого уровня |
| `item` | предмет призыва, который запускает ивент с подставки (`soulscraft:rotten_horn`, Гнилой горн) |
| `flow` | зона и путь: `zone_chunks` (зона — столько чанков в стороне, чанк ядра в середине), `below_blocks` и `above_blocks` (высота карты путей от ядра), `rebuild_min_ticks` (карта строится заново не чаще), `spawn_blocks` (точки появления волны — на таком расстоянии от ядра, от и до), `telegraph_ticks` (сколько точки видны до волны), `participant_grace_ticks` (сколько зона может пустовать до провала), `drain_blocks` (с какого расстояния моб вытягивает силу). Кроме зоны 3 × 3 — предложение кода |

`defense.breach` — что ломает громила (06-altar.md, «Пролом громилы»):

| Поле | Что это |
| --- | --- |
| `hits_by_hardness` | пары `[твёрдость до, ударов]`: первая пара, где твёрдость блока не выше, даёт число ударов; блок твёрже последней пары не ломается. Г12: ≤ 2 — 1, ≤ 5 — 2, ≤ 50 (обсидиан) — 6 |
| `attack` | удар громилы, которым он бьёт стену (его тики — из атаки) |
| `never_namespaces` | пространства имён, которые не ломаются никогда: `rustcraft:` целиком (у рельсов монорельса нет block entity, ответ RustCraft 2026-11-13) |
| `never_blocks`, `never_prefixes` | отдельные блоки и начала id, которые не ломаются. Блоки алтаря и знамёна, любые блоки с block entity и неразрушимые (твёрдость < 0) не ломаются и без списка |
| `target` | на кого идут мобы |
| `waves` | волны: `wave` и список `mobs` (`type` — ванильный тип, id или ключ моба SoulsCraft; `count`, `armored` — сколько из них в броне, `health_mult`, `name` — для заметок) |

Ивенты сейчас: `test_zombies` (ступень 1, Гнилой горн), `grave_night` (2, Горн мертвецов), `claw_storm` (3, Горн бури), `last_stand` (4, Горн бездны); [10-survival.md](../docs/design/10-survival.md).

## Естественный спавн: `natural`

`natural.mobs` — строки, которые сервер добавляет в список спавна монстров верхнего мира (гипотеза Г14; `soulscraft_rules::natural::extras`).

| Поле | Что это |
| --- | --- |
| `mob` | id моба |
| `biomes` | части имени биома: `forest` берёт `birch_forest` и `dark_forest` |
| `biomes_with_zombie` | вместо `biomes`: любой биом, где в списке уже есть зомби |
| `weight`, `min`, `max` | вес и размер группы, как у ванильных строк (зомби в равнинах — 95) |
| `min_y`, `max_y` | высота точки, от и до |

Два ряда одного моба (громила: пещеры и пики) — оба работают, в список он попадает один раз.

`natural.lurker` — свой спавнер удильщика: `biomes` (имена целиком), `every_ticks` и `chance` (как часто и с каким шансом пробовать у каждого игрока), `radius_blocks` (от и до по горизонтали от игрока), `max_y` (вода не выше), `near_cap` и `near_blocks` (не больше стольких удильщиков в этом радиусе).

## Осколок души: `soul_shard`

`item`, `chance` и `count` — у обычного моба, `elite_chance` и `elite_count` — у элитного (гипотеза Г15). Роняет моб SoulsCraft, убийство которого книга засчитала игроку; мобы спавнеров не роняют.

## Горн с врагов: `horn_drop`

`item` и `chance` — горн обычного моба SoulsCraft (Горн мертвецов, 0,5%), `elite_item` и `elite_chance` — элитного (Горн бури, 3%; гипотеза Г18, раунд 3). Роняет та же засчитанная смерть, что и осколки, вместе с головой (`trophies.json`, `drops.head.world`) и частями брони из `loot` моба.

## Как добавить моба или поменять числа

1. Поменять число здесь.
2. Если поменялись тики атаки, поправить ключи клипа в `assets/models/mobs/<моб>.py` и пересобрать модели. Сборка напомнит: она падает на расхождении меток.
3. Витрина подхватит новые числа после сборки (`docs/showcase/js/data.js` генерируется из этого файла).

## Алтарь: `altar.json`

Уровни алтаря, гнёзда, знамёна и положение предмета на подставке — для блоков (`assets/models/blocks/altar.py` строит по ним уровни), Blender и витрины (`#altar`). Источник — [06-altar.md](../docs/design/06-altar.md); числа знамён — гипотеза Г10, клетки гнёзд и положение предмета — предложения.

| Поле | Что это |
| --- | --- |
| `levels[]` | `level`, `size` (сторона квадрата), `corner` (блок на углах кольца или `null`), `sockets` (клетки гнёзд кольца `[x, z]`, ядро в `(0, 0)`, x восток, z юг), `spawn_boost`, `unlocks` |
| `pedestal_item` | предмет над подставкой: `height_px` — центр над низом подставки, `scale`, `spin_deg_per_tick`, `bob_px`, `bob_ticks` |
| `modifiers[]` | знамя: `id`, `banner` (id блока), `name`, `short`, `emblem`, `effect` (`power` — к силе P, `wave_size` — доля врагов в волне, `rest_seconds` — к передышке, `altar_health` — доля здоровья алтаря, `kin` — группа мобов и `kin_share` — доля слотов волны, которую знамя рода отдаёт своей группе), `text`, `reward` (`more`, `less`, `same`), `opposite` |
| `sample_banners` | какие знамёна стоят в гнёздах собранных уровней в Blender и витрине, по порядку гнёзд |
| `kin_names` | русские имена групп мобов |
| `kin_rule` | как знамя рода меняет волну, текстом (код — `soulscraft_rules::event::kin_bias`) |
| `spawn_boost` | учащённый спавн, вторая роль алтаря (итерация 3, П4; все числа — гипотезы): `extra_passes` — лишние проходы спавна по каждому чанку сектора за тик для уровней 1–4; `sector_radius_chunks` (1: сектор 3 × 3 чанка); `start_chunks` — на сколько чанков от алтаря начинается центр сектора; `drift_ticks` — раз в сколько тиков он на чанк ближе; `foreign` — монстры других биомов в списке спавна сектора (`type`, `weight`, `min`, `max`); `soulscraft_weight` — вес каждого моба SoulsCraft (без элитных и только водных); `kin_weight` — знамя рода умножает веса своей группы на `1 + kin_weight · знамён`; `kin_vanilla` — ванильные мобы каждой группы (с раунда 14: магмовый куб — слизни, иссушённый скелет — нежить, хоглин — звери, зоглин — нежить и звери) |

## Трофеи: `trophies.json`

Описание диорамы, отвергнутые варианты и шансы трофеев — для витрины (`#trophies`, блок «Трофей: диорама» на странице моба) и мода. Сцены, свет и частицы диорам — не здесь, а в `assets/models/blocks/dioramas.py` (`SCENES`), числа для мода — в `assets/rigs/<моб>.trophy.json`. Источник — [09-trophies.md](../docs/design/09-trophies.md); шансы — предложения.

| Поле | Что это |
| --- | --- |
| `diorama` | `name`, `text` (что это), `item` (как ставится), `plaque` (что на табличке), `view_blocks` (дальность отрисовки block entity), `particles_blocks` (дальность частиц) |
| `rejected` | отвергнутые варианты чучела (раунд 6): `round`, `commit`, где они ещё есть, `text`, `variants` |
| `drops` | `banner_step` — множитель награды знамён: шанс каждой части брони × `(1 + banner_step · (сложнее − проще))`, не меньше 0 (головы: +1 за «сложнее», −1 за «проще», не меньше одной); `head` (`event` текстом, `world` и `world_elite` — доли), `armor` (`event` — доля за победу на каждую часть брони мобов ивента из их `loot`), `diorama` (`event`, `min_altar_level`; только мобы SoulsCraft: у зомби диорамы нет) |
| `tiers` | награда ступени ивента сверх трофеев ([11-summons-rewards.md](../docs/design/11-summons-rewards.md), Г19): `tier`, `shards` (осколков всегда), `item` и `chance` (предмет ступени; шанс × множитель знамён, не больше 1) |

Какой моб элитный, задаёт `mobs.json`: поле `elite: true` (громила). Книга открывает такую запись быстрее, у головы свой шанс.

## Лут структур: `loot.json`

Что мод добавляет в ванильные таблицы лута, когда они грузятся (хук `native_loot_table_load`; [11-summons-rewards.md](../docs/design/11-summons-rewards.md), Г17 и Г18). Читает крейт `mod/soulscraft/loot` (копию пишет `mod/sync.ps1`). Пулы таблицы остаются, добавляются новые.

| Поле | Что это |
| --- | --- |
| `chests` | `table` (`minecraft:chests/...`), `item` (горн), `chance` — горн в сундуке этой структуры |
| `chest_shards` | `item`, `chance`, `count` [от, до] — осколки в каждом сундуке из `chests` |
| `killed_by_player` | `tables` (таблицы мобов `minecraft:entities/...`), `item`, `chance` — только если моба убил игрок |

## Книга охотника: `book.json`

Ступени записи о враге и записи алтаря — для витрины (`#book`) и мода. Источник — [08-guide-book.md](../docs/design/08-guide-book.md); пороги — гипотеза Г11.

| Поле | Что это |
| --- | --- |
| `stages[]` | `id`, `n` (0..4), `name`, `kills` и `elite_kills` (убийств для ступени, `null` — не встречен, 0 — встречен), `when`, `opens` |
| `credit` | кому засчитывается убийство: `radius_blocks`, `window_seconds`, `spawner_weight` |
| `altar_entries[]` | записи алтаря и ивентов: `id`, `name`, `when`; `text` — что книга пишет на открытой записи (основа, знамёна, оборона алтаря) |
| `sections` | разделы книги |
| `action_bar` | сообщение над панелью предметов при новой ступени: `{mob}`, `{stage}` |

Мод берёт `book.json` вкомпилированным в крейт (копия `mod/soulscraft/rules/data/book.json` от `sync.ps1`), как `mobs.json`. Записи раздела «Враги» — все мобы `mobs.json`: `mobs` и строки `vanilla.groups` (одна запись на строку со всеми её `types`); новый моб в данных получает запись без кода. Страница берёт из моба `name`, `role`, `look`, `spawn`, `stats`, `attacks` (`name`, `clip`, фазы, `tell`), `behavior` (список — тактика), `loot`, `hitbox` (масштаб модели в окне), из `trophies.json` — шанс головы, из `events` — волны с этим мобом. Прогресс игрока мод хранит в его постоянных данных под ключом `soulscraft:book` ([../prototypes/p9-book.md](../prototypes/p9-book.md)).
