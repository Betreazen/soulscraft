# Модели мобов и блоков

Модели, текстуры и анимации мобов SoulsCraft и модели блоков строятся кодом в Blender 5.2. Правила — [05-art-pipeline.md](../../docs/design/05-art-pipeline.md), числа атак — [data/mobs.json](../../data/mobs.json).

## Как пересобрать

Из корня репозитория:

```text
"C:\Program Files\Blender Foundation\Blender 5.2\blender.exe" --background --factory-startup --python assets/models/build.py
```

Сборка строит все модели из `mobs/*.py` с нуля и перезаписывает:

| Файл | Что это |
| --- | --- |
| `assets/models/<моб>.glb` | меши, текстура с фильтром `NEAREST`, все клипы как анимации glTF |
| `assets/rigs/<моб>.rig.json` | риг для игры, формат в [assets/rigs/README.md](../rigs/README.md) |
| `assets/rigs/<моб>.trophy.json` | голова моба и его диорама для отрисовки block entity (см. «Трофеи») |
| `assets/textures/entity/<моб>.png` | текстура ванильной плотности |
| `assets/soulscraft/models/item/*.json` и `textures/item/*.png` | модели предметов: оружие, шлемы, значки |
| `assets/soulscraft/equipment/*.json` и `textures/entity/equipment/humanoid/*.png` | броня ванильной формы, текстура 64×32 |
| `assets/models/mobs.blend` | все модели, по сцене на моба, для глаз автора |
| `assets/soulscraft/models/block/*.json`, `blockstates/*.json`, `textures/block/*.png` | блоки: модели из элементов, состояния, текстуры 16×16 (см. «Блоки») |
| `assets/soulscraft/textures/mob_effect/*.png` | значки эффектов мода 18×18, как у ванили (`effects.py`): `bleeding` — кровотечение |
| `assets/soulscraft/particles/*.json`, `textures/particle/*.png` | свои типы частиц диорам: `horizon:behaviour` и спрайт 8×8 (см. «Трофеи») |
| `assets/models/blocks_<набор>.glb`, `altar_level_1..4.glb`, `blocks.blend` | блоки и собранные уровни алтаря для витрины и для глаз автора |
| `assets/site/<моб>.glb`, `assets/site/altar_level_4.glb` | модели для сайта: моб с оружием в руках, все клипы; копия алтаря четвёртого уровня (см. «Модели для сайта») |
| `docs/showcase/js/*.js` | те же данные для витрины (это делает `embed.py`, реестр блоков `blocks.js` — `build_blocks.py`) |

Блоки собирает `build_blocks.py`; `build.py` вызывает его после мобов, а отдельно он запускается так:

```text
"C:\Program Files\Blender Foundation\Blender 5.2\blender.exe" --background --factory-startup --python assets/models/build_blocks.py
```

Сборка падает, если у атаки из `mobs.json` нет клипа, метки клипа не совпали с тиками атаки, клип не той длины или на метке нет ключа; если клип хватки не круг длиной `grab_max_ticks`; если у кубов есть совпадающие грани (см. «Совпадающие грани»); и если фигурка диорамы или голова выходит из блока или её грани совпадают с гранями модели диорамы, пола или стены (см. «Трофеи»).

Проверки и картинки:

```text
blender --background --factory-startup --python-exit-code 1 --python assets/models/selfcheck.py
blender --background assets/models/mobs.blend --python assets/models/preview.py -- revenant
blender --background assets/models/mobs.blend --python assets/models/preview.py -- all
blender --background assets/models/blocks.blend --python assets/models/preview.py -- blocks
blender --background assets/models/mobs.blend --python assets/models/preview.py -- trophies
```

`-- trophies` рисует головы и диорамы всех мобов: днём, спереди, ночью, издалека и фигурку крупно (см. «Трофеи»), `-- trophies:brute,lurker` — только этих мобов. `-- blocks` рисует каждый блок набора алтаря (в три четверти и спереди; знамёна — со стороны полотнища) и каждый уровень алтаря (в три четверти, сверху и спереди, крупнее) в `previews/altar_*.png` и листы `altar_blocks_sheet.png`, `altar_levels_sheet.png`.

`selfcheck.py` сверяет перевод осей (см. ниже), меч латника (см. «Оружие-спрайт»), сам поиск совпадающих граней, файлы блоков и файлы трофеев (см. «Трофеи»), код выхода 1 при ошибке. `preview.py` рисует в `previews/` только то, что у моба есть: покой спереди, сбоку и в три четверти (летающему — ещё снизу), стойку `idle`, крупный план со стороны оружия, каждый флаг состояния включённым, замах, удар и окно каждой атаки (летающему — ещё снизу) и по ключевому кадру каждого другого клипа, плюс общий лист `<моб>_sheet.png`. Старые картинки моба он сначала удаляет. Кадр подбирается по размеру модели: масштаб задаёт покой, поза с длинным выносом получает кадр шире, но не больше чем в 1,6 раза; что дальше (летящий болт), в кадр не берётся. Свет тот же, что в витрине.

## Модели для сайта

Сайт проекта читает [site.toml](../../site.toml) в корне репозитория и показывает `.glb` как есть, без кода витрины. В `assets/models/<моб>.glb` оружия в руках нет: витрина вешает его на гнёзда сама. Поэтому сборка (`site_models.py`) пишет в `assets/site/` вторую копию каждого моба:

- предметы из гнёзд моба (`m.hold`) входят в файл: это те же объекты превью, что сборка уже поставила под гнёзда по цепочке игры (`Kᵀ · held_matrix`, см. «Оси: Blender и игра»). Молот громилы, меч латника, серпы ловчего; щит латника и арбалет стрелка — части модели и так;
- все клипы, анимация узлов glTF, без скелета; материалы и текстуры внутри файла;
- части, видные только под флагом состояния (красные глаза ярости громилы), не входят: витрина без флага их тоже прячет;
- `altar_level_4.glb` — копия собранного уровня алтаря, без анимации.

Сборка падает, если файл больше 4 МБ или все вместе больше 16 МБ (пределы сайта). Предмет в `assets/site/<моб>.glb` совпадает с цепочкой витрины (`SC.heldMatrix` в `viewer.js`) до 4·10⁻⁷ на каждом тике каждого клипа (проверено в three.js без кода витрины).

Картинка `site/preview.webp` для `site.toml` (1280×720: алтарь четвёртого уровня целиком в середине, громила с поднятым молотом сбоку, латник, ловчий, стрелок и сорокопут вокруг, свет превью) рисуется отдельно и в детерминированную сборку не входит:

```text
blender --background assets/models/mobs.blend --python assets/models/preview.py -- site
```

Текст карточки мода — `site/description.md`.

## Детерминизм

Повторная сборка даёт побайтно те же `.glb`, `.rig.json`, `.png`, `.json` и `.js`. Это проверено двойной сборкой со сравнением хешей. Исключение — `mobs.blend` и `blocks.blend`: Blender пишет в него адреса памяти общих массивов мешей и списков интерфейса, они меняются от запуска к запуску даже у пустой сцены с одним квадратом. Игра и витрина `.blend` не читают.

## Как добавить моба

Нужен один файл `mobs/<id>.py`, где `<id>` — `id` моба из `data/mobs.json`. Общие файлы трогать не нужно.

```python
from items import HANDHELD_PARENT, Sprite
from paint import Material
from rig import M, R, pose

ID = 'brute'
PALETTES = {'hide': ['#2b2118', '#3d2f22', '#52402e', '#66503a'],   # тёмный → светлый
            'iron': Material(['#3a3836', '#55514d', '#6e6964'], noise=0.6), ...}   # свой шум
TEXTURE = (128, 128)          # необязательно; по умолчанию 64×64, если кубы не влезут — больше

def model(m):
    m.part('root', (0, 24, 0))
    body = m.part('body', (0, 12, 0), parent='root')         # точка поворота, пиксели модели игры
    body.cube((-6, -14, -4), (12, 14, 8), 'hide', decal=my_decal, inflate=0)
    m.part('arm_r', (-8, 0, 0), parent='body').cube((-4, -2, -2), (4, 18, 4), 'hide')
    m.socket('socket_hand_r')                                  # ванильная точка кисти (-1, 10, -2)
    m.hold('socket_hand_r', CLEAVER)                           # предмет из SPRITES или ITEMS

def clips(c, mob):                                             # mob — запись из mobs.json
    idle = c.clip('idle', 40, loop=True)
    idle.key(0, {}).key(20, {'body': R(2, 0, 0)}).key(40, {})
    a = c.attack('attack_slam', next(x for x in mob['attacks'] if x['clip'] == 'attack_slam'))
    a.key(0, {}, 'out')
    a.key(a.at('hit') - 2, {'arm_r': R(-150, 0, 0)}, 'in')     # замах, потом быстрый удар
    a.key(a.at('hit'), {'arm_r': R(-30, 0, 0), 'body': R(25, 0, 0) + M(0, 1, -2)}, 'out')
    a.key(a.at('recover'), {...}, 'hold')
    a.key(a.at('end'), {})

CLEAVER = Sprite('brute_cleaver', cleaver_sprite, parent=HANDHELD_PARENT, palettes=PALETTES)  # см. «Оружие-спрайт»
ITEMS = []            # необязательно: модели из элементов (items.Item): шлемы, объёмное оружие
SPRITES = [CLEAVER]   # необязательно: спрайты (items.Sprite): оружие в руке и плоские значки
ARMOR = []            # необязательно: броня ванильной формы (items.Equipment)
```

Потом пересобрать. Для витрины — файл `docs/showcase/js/mobs/<id>.js` (см. [docs/showcase/README.md](../../docs/showcase/README.md)).

Файлы `mobs/_<имя>.py` — фигуры только для витрины: игрок в сценах и реквизит (навес, стена, ударная волна). Без `rig.json` и без записи в `mobs.json`, текстура в `assets/models/textures/`. Сцена ставит реквизит полем `props` (см. [docs/showcase/README.md](../../docs/showcase/README.md)).

## API

**Модель** (`rig.Model`, всё в пикселях пространства модели игры: +x — левая сторона моба, +y вниз, −z вперёд; углы в градусах):

| Вызов | Что делает |
| --- | --- |
| `m.part(name, pivot, parent=None, rot=(0,0,0), glow=False, state=None)` | часть. `pivot` — абсолютная точка поворота в позе покоя, как `PartPose.offset` у корня; относительную сборка считает сама. `rot` — поворот покоя: наклонный куб делается частью с поворотом. `state='rage'` — часть видна только под флагом состояния моба, `state='!lit'` — только без него (глаза ярости громилы) |
| `part.cube(origin, size, mat, inflate=0, glow=False, decal=None, grain=1, faces=все, share=None, mirror=False, coplanar_ok=None)` | `addBox` в кадре части. Размеры целые: пиксель куба — тексель. `inflate` (число или три) растягивает геометрию, но не UV. `share=куб` — взять область листа другого куба того же размера (`inflate` у каждого свой), `mirror=True` — как `.mirror()` у ванили (левые руки и ноги). `coplanar_ok='почему не видно'` — исключение из проверки граней, только с доказательством |
| `m.socket(name, parent=None, offset=None, rotate=None)` | гнездо. `socket_hand_r` и `socket_hand_l` по умолчанию под `arm_r` и `arm_l` в точке `(∓1, 10, −2)` с `rotX(−90)·rotY(180)`. Для своей руки — `offset` в центре низа кисти на передней грани |
| `m.hold(socket, item)` | предмет в руке. Blender ставит его по цепочке игры с `display.thirdperson_*hand` |

**Текстура** (`paint.py`). Лист раскладывается сам. Каждая грань заливается палитрой материала с шумом; верх светлее, низ темнее, на боковых гранях лёгкий градиент. Потом рисует `decal(face)`: `face.name` — `front`, `back`, `left`, `right`, `top`, `bottom` (left — левая сторона моба), координаты грани как на листе (x вправо, y вниз, у боковых граней y = 0 — верх). Цвет — `'#rrggbb'`, `'#00000000'` (дыра) или `(материал, ступень)`, отрицательная ступень считается от светлого конца.

Шум как у ванили: один-два тона внутри материала, пятнами по несколько текселей, и немного мелкой ряби по краям пятен. Настройки по умолчанию — `paint.NOISE` (`noise` — размах пятен в ступенях палитры, `patch` — размер пятна в текселях, `fine` — рябь). Свой шум у материала — `Material([...], noise=, patch=, fine=)` вместо списка; `grain` у куба умножает шум, `grain=0` — ровный цвет. Ржавчину, грязь и трещины не сыплют по всей грани: одиночные яркие пиксели читаются как гравий. Их ставят руками: потёки под заклёпками и щелями, пятна там, где стоит вода (нижние края, верх шлема), бурый переход вокруг оранжевого.

| Метод грани | Что рисует |
| --- | --- |
| `px(x, y, c)`, `rect(x, y, w, h, c)`, `line(x0, y0, x1, y1, c)` | пиксель, прямоугольник, линию |
| `outline(c, sides='tblr')` | рамку по краям грани |
| `rows(rows, key, x=0, y=0)` | карту пикселей: строки символов, `key` — символ → цвет; символа нет в `key` — тексель не трогается |
| `streak(x, y, length, c, tail=None)` | потёк вниз от точки; `tail` — цвет последнего текселя |
| `patch(x, y, w, h, c, density=0.55, seed=0)` | пятно с рваным краем внутри рамки, сплошное в середине |
| `edge(c, where=None)` | обводку спрайта: непрозрачные тексели, у которых сверху, снизу, слева или справа пусто |
| `solid(x, y)`, `get(x, y)` | непрозрачен ли тексель, его цвет |
| `speckle(c, доля, seed=0)` | редкие одиночные тексели; только близким к основе цветом |

**Клипы** (`rig.Clips`):

| Вызов | Что делает |
| --- | --- |
| `c.clip(name, length, loop=False, markers=None)` | клип; кадр Blender = тик |
| `c.attack(name, attack)` | клип атаки из записи `mobs.json`: длина и метки по её тикам |
| `clip.key(frame, pose, ease)` | ключ: полная поза, части вне позы — в покое. `ease` — как кривая уходит к следующему ключу |
| `clip.at('hit')` | кадр метки |
| `R(x, y, z)`, `M(x, y, z)`, `S(x, y, z)`, `+` | поворот (градусы), сдвиг (пиксели) и масштаб части по её осям после поворота; `+` складывает повороты и сдвиги и перемножает масштабы. `S(0)` прячет часть, `S(1.2)` — одинаково по осям |
| `pose(a, b, part=J)`, `lerp(a, b, f)` | сложить позы, сдвинуть позу к другой (масштаб тоже линейно) |

`ease`: `out` — быстро в позу замаха и мягкая остановка; `in` — медленно, потом быстро в удар; `snap` — почти стоит, потом рывок (отпускание задержанного удара); `inout`, `slow` — мягко с обеих сторон (дыхание, восстановление); `back` — с перелётом; `hold` — замереть до следующего ключа; `linear`.

Как ставить ключи атаки, чтобы замах читался: поза замаха к `hit − 2` с `out` или `inout`, последние два тика до `hit` — `in` или `snap`, на `hit` — поза контакта, после `recover` — `hold` («застрял»), к `end` — `slow` назад в стойку. Противодвижение перед ударом — в позе замаха: меч назад, корпус в обратную сторону.

Масштаб и флаги состояния. Что показывает или прячет клип, делается масштабом в ключах: приманка удильщика гаснет `S(0)` на 4-м тике замаха, блик арбалетчика вне прицела сжат в ноль. Что зависит от состояния моба, а не от клипа, — флагом части: глаза ярости громилы видны, пока у моба флаг `rage`. Масштаб растягивает тексели, поэтому для формы (сжатие слизи) он не берётся: слизь сжимается слоями, как магмовый куб.

## Совпадающие грани

Две грани в одной плоскости мерцают друг сквозь друга (z-fighting): в игре и в витрине глубина у них одна. Сборка ищет такие пары (`zfight.py`) и падает со списком: моб, клип, тик, части и номера кубов.

- Пара — грани в одной плоскости (с точностью 0,001 пикселя), которые перекрываются больше чем на 0,001 квадратного пикселя и смотрят в одну сторону. Грани, смотрящие навстречу, считаются парой, только если один из кубов плоский: у двух объёмных кубов, которые касаются, обе такие грани внутри.
- Проверяются все кубы со всеми, в одной части и в разных, с `inflate`, в позе покоя и на каждом тике каждого клипа; предмет из элементов в гнезде — по цепочке игры; элементы моделей предметов (шлемы, молот) — между собой. Спрайты (выдавленные мечи и серпы) не проверяются: клинок в 1 пиксель не лежит в плоскости грани куба.
- Исправление — 0,1 пикселя, как `CubeDeformation` у ванили: куб, который должен быть сверху, получает `inflate` 0,1 по оси общей плоскости, или спрятанный куб утапливается на 0,1. Почему 0,1: точность глубины на расстоянии d при ближней плоскости n и 24-битном буфере — около d² / (n · 2²⁴). В игре (n = 0,05 блока) на 32 блоках это 0,02 пикселя, в витрине (n = 0,1) на 30 блоках — около 0,01 пикселя; 0,1 пикселя с запасом больше и меньше десятой доли текселя, силуэт не меняется.
- Грани, целиком скрытые внутри другого куба, допустимы, только если они не в плоскости видимой грани. Исключение `coplanar_ok` — только для доказанно скрытого случая, с причиной в файле моба. Сейчас его нет ни у одного куба.

## Оружие-спрайт

Ванильные мечи, топоры и кирки — не модели из кубов, а спрайт 16×16 с родителем `minecraft:item/handheld`. Игра выдавливает его сама (`ItemModelGenerator`): спрайт целиком спереди и сзади и по боковой грани на каждом краю текселя, за которым пусто; толщина 1 пиксель (z от 7,5 до 8,5). Оружие SoulsCraft в руке делается так же, тогда в кулаке оно читается как клинок, а не как палка. Модель предмета — три строки:

```json
{"parent": "minecraft:item/handheld", "textures": {"layer0": "soulscraft:item/<имя>"}}
```

`display` берётся у родителя: в руке `thirdperson_righthand` — rotation `[0, -90, 55]`, translation `[0, 4, 0.5]`, scale `0,85`. Blender (превью в руке) и витрина повторяют выдавливание и эту цепочку.

Оружие объявляется в файле моба, общие файлы не трогаются:

```python
from items import HANDHELD_PARENT, Sprite

def cleaver_sprite(c):                 # c — грань 16×16 со всеми методами из «Текстуры»
    for y in range(16):
        for x in range(16):
            a, d = x - y, x + y - 15   # a — вдоль клинка (вверх-вправо), d — поперёк
            if a >= -2 and -3 <= d <= 2:
                c.px(x, y, ('iron', 2))
            ...
    c.edge('#1e1b19')                  # тёмная обводка, как у ванили

CLEAVER = Sprite('brute_cleaver', cleaver_sprite, parent=HANDHELD_PARENT, palettes=PALETTES, name='Тесак')
# или картой пикселей:
# Sprite('brute_cleaver', rows=[16 строк по 16 символов], key={'#': '#1e1b19', 'i': ('iron', 2)},
#        parent=HANDHELD_PARENT, palettes=PALETTES)
SPRITES = [CLEAVER]

def model(m):
    ...
    m.hold('socket_hand_r', CLEAVER)
```

- Можно и `rows` с `key`, и `draw` вместе: сначала рисуется карта, потом функция.
- Раскладка как у ванильного меча: рукоять внизу слева, клинок по диагонали, остриё в правом верхнем углу. Кулак приходится на точку предмета (4, 4) в пикселях (y вверх), это угол текселей x 3–4, строки 11–12 (строки идут сверху вниз). Рукоять должна закрывать это место, иначе моб держит оружие за клинок.
- Пустой тексель — дыра насквозь, у её краёв появляются боковые грани (зазубрина на клинке).
- Без `parent` спрайт — плоский значок `item/generated` (нагрудник латника).
- Объёмному оружию (молот громилы с бойком-кубом) спрайт не нужен: это `items.Item` из элементов со своим `display`, как раньше.
- `selfcheck.py` проверяет меч латника: PNG совпадает с тем, что рисует файл моба, превью в Blender — его выдавливание, кожаная рукоять закрывает точку (4, 4). Своё оружие проверяется глазами в `preview.py`: крупный план стойки показывает предмет в кулаке.

## Блоки

Блоки — ванильные JSON-модели из элементов (кадр блока: пиксели 0..16, +x восток, +y вверх, −z север, начало в северо-западном нижнем углу). Мод их не рисует сам: игра читает модель, состояния и текстуры как у любого блока. Правила — [05-art-pipeline.md](../../docs/design/05-art-pipeline.md), раздел «Блоки».

Набор блоков — файл `blocks/<имя>.py`. Общие файлы трогать не нужно:

```python
from blocks import Block, Structure, Texture
from items import Sprite
from paint import Material

SET = 'altar'                                    # набор: все его модели в blocks_altar.glb
PALETTES = {'stone': Material([...], noise=0.75, patch=4), 'bone': [...]}

def stone_draw(f):                               # f — грань 16×16 с методами из «Текстуры»
    f.line(2, 3, 5, 6, ('stone', 0))
TEXTURES = [Texture('altar_stone', 'stone', stone_draw)]     # soulscraft:block/altar_stone

def pillar(m, part):                             # m — модель одной клетки; part — сегмент
    if part == 'bottom':
        m.box((1, 0, 1), (15, 3, 15), {'up': 'altar_stone', 'down': 'altar_stone', 'side': 'altar_slab_side'})
        m.box((3, 3, 3), (13, 16, 13), 'altar_pillar_side', faces=('north', 'south', 'west', 'east'))
    else:
        ...
BLOCKS = [Block('altar_pillar', 'Колонна алтаря', pillar, part=('bottom', 'top'), on_slab=True,
                item=Sprite('altar_pillar', pillar_icon, palettes=PALETTES))]
SPRITES = [...]                                  # значки предметов и простые предметы (горн)

def structures(blocks):                          # необязательно: собранные постройки
    s = Structure('altar_level_1', 'Алтарь, уровень 1')
    s.piece(blocks['altar_pillar'], (2, 1, 2), on_slab=True, ring=2, kind='corner', group='corner 2,2')
    return [s]
```

| Вызов | Что делает |
| --- | --- |
| `Texture(id, mat, draw=None, grain=1, image=None)` | текстура 16×16 `soulscraft:block/<id>`: заливка материала без шва (`paint.fill_tile`), потом `draw(f)`. `image=paint.Image` — готовая картинка (полотнище знамени, вырезанное из холста 16×32) |
| `m.box(from, to, tex, faces=все, uv=None, rotation=None, glow=0, shade=True)` | элемент. `tex` — id текстуры или словарь по граням (`north`…, `side`, `end`, `all`). `faces` — оставить только видимые грани. `uv` — свой прямоугольник грани, иначе ванильный по положению. `rotation=('x', 22.5, (8, 11, 4.5))` — одна ось, −45…45 шагом 22,5. `glow` — `light_emission` 0…15 на элементе |
| `Block(id, name, build, states=None, part=None, facing=False, on_slab=False, item='block', role='')` | блок. `build(m, **состояние)` вызывается на каждое сочетание `states` (`{'lit': (False, True)}`) и сегмента `part`. `facing=True` — состояния north/east/south/west, модель строится лицом на север, поворачивает blockstate. `on_slab=True` — ещё модели `<модель>_on_slab` на 8 пикселей ниже и состояние `on_slab`. `item='block'` — предмет берёт модель блока; `Sprite` с id блока — плоский значок, как у двери |
| `Structure(id, name)`, `s.place(block, (x, y, z), state, facing, on_slab, **meta)`, `s.piece(...)` | постройка в клетках (x восток, y вверх, z юг; клетка (0, 0, 0) в начале координат). `piece` ставит все сегменты блока снизу вверх. `meta` (кольцо, вид, группа) уходит в витрину как есть |

Имена моделей: id блока, потом `_<значение>` каждого небулевого состояния (сегмент тоже), потом `_<состояние>` каждого включённого булевого: `altar_pillar_bottom`, `altar_brazier_lit`, `banner_weight_top_on_slab`.

Что проверяет сборка и `selfcheck.py`:

- Элементы в пределах −16…32 пикселя, поворот по одной оси кратен 22,5 и не больше 45°, UV внутри плитки 16×16, `light_emission` 0…15, каждая текстура и модель на месте, каждый вариант состояния называет существующую модель, предмет блока — модель блока или спрайт с PNG.
- Совпадающие грани (`zfight.py`) — внутри каждой модели, в каждом блоке, собранном из сегментов на плите алтаря, и в каждой постройке со всеми блоками на своих местах. Сборка падает на любой паре.
- UV по умолчанию — ванильный: грань берёт ту часть плитки, над которой стоит. Грань выше блока (язык пламени) берёт те же строки, что внутри блока; грань, которая пересекает край блока (навершие колонны), сдвигается в плитку на сколько нужно.
- На краю блока грань получает `cullface`, как у ванили.

Текстуры блоков: плитка без шва там, где грань — целая грань блока (плита, камень); шум пятнами, без россыпи; затенения граней нет — блоки игра затеняет по направлению сама. Детали ставятся руками, как у мобов: швы плит, мох в одном шве, трещина, инкрустация кости.

Витрина ставит блок по реестру `docs/showcase/js/blocks.js`: узел `<модель>` из `blocks_<набор>.glb` в кадре блока, поворот blockstate вокруг центра клетки, модель `_on_slab` — тот же узел на 8 пикселей ниже (см. [docs/showcase/README.md](../../docs/showcase/README.md)). Уровни алтаря витрина берёт из `altar_level_N.glb` — их собирает Blender из тех же моделей связанными копиями.

Блок, который целиком рисует block entity (голова моба), строится функцией без элементов: модель получает только текстуру частиц (`particle=`), а состояния, которые читает только отрисовка, идут в `entity_states` — они есть в blockstate, но все значения называют одну модель:

```python
Block('revenant_head', 'Голова: Латник-мертвец', no_elements, entity_states={'rotation': tuple(range(16))},
      particle='trophy_bone', item=ICONS['revenant'])
```

Такие блоки в `blocks.js` помечены `entity: true`, в glb и в сценах Blender их нет.

Предмет головы `<моб>_head` — объёмная модель (`HeadItem` в `blocks/trophies.py`): кубы головы из файла трофея как элементы, в масштабе головы на полу, на текстуре самого моба (копия в `textures/item/<моб>_head.png`), с `display` шлемов (`items.HELMET`: на голове — тождество, головы крупнее блока в инвентаре, на земле, в рамке и в руке — мельче) и ванильным видом от первого лица. На голове игрока она садится, как голова на мобе, по центру главного куба (`head.icon`). Поворот части становится поворотом элемента: четверти — перестановка сторон коробки, остаток — одна ось с шагом 22,5° до 45°; поэтому стебель удильщика и корни слизи наклонены чуть иначе, чем в риге, и грань, повёрнутая на четверть, держит тексели неповёрнутыми. Сборка падает, если элемент выходит за −16..32 пикселя.

## Трофеи

Головы мобов и диорамы ([09-trophies.md](../../docs/design/09-trophies.md)). Игра рисует голову и фигурку в диораме отрисовкой block entity тем же ригом и текстурой, что моба; `trophies.py` считает, что для этого нужно, и пишет рядом с ригом `assets/rigs/<моб>.trophy.json`. Сборка вызывает его после мобов, из только что записанных `rig.json`.

Моб задаёт свои трофеи словарём `TROPHY` в своём файле и позу — клипом `trophy` (все ключи необязательны):

```python
TROPHY = {
    'head': {'parts': ['head'], 'drop': [], 'rot': None, 'scale': 0.9, 'icon': None},
    'clip': 'trophy',      # клип позы в диораме, по умолчанию trophy
    'flags': ['rage'],     # флаги состояния, включённые в диораме (глаза ярости громилы)
}

def trophy_clip(c):        # из clips(c, mob): поза трофея, 80 тиков по кругу, медленное дыхание
    t = c.clip('trophy', 80, loop=True)
    t.key(0, TROPHY_POSE)
    t.key(40, pose(TROPHY_POSE, body=R(1.5, 0, 0) + M(0, 0.3, 0)))
    t.key(80, TROPHY_POSE)
```

| Ключ | Что это |
| --- | --- |
| `head.parts` | верхние части головы, с детьми. `drop` — части, которые не входят (хвост удильщика). `rot` — поворот верхней части вместо её места в позе покоя (капюшон ловчего прямо). `scale` — масштаб головы; сборка падает, если голова выходит из блока. `icon` — `(часть, куб)`, чья лицевая грань станет значком предмета; по умолчанию первый куб верхней части |
| `clip` | клип позы диорамы |
| `flags` | флаги состояния частей, которые в диораме включены |

**Сцена диорамы** — `blocks/dioramas.py`, по записи на моба в `SCENES`:

```python
SCENES = {
    'brute': dict(build=brute, light=5, turn=-15,
                  figure=dict(lo=(-7.5, 3.25, -6.5), hi=(7.5, 15.75, 4.25), floor=3.25),
                  particles=[dict(type='ember', every=5, box=((4, 3.5, 3), (12, 4, 10)))],
                  text='Место удара: ...'),
}
```

| Поле | Что это |
| --- | --- |
| `build(m)` | элементы сцены поверх общей подставки (`plinth`): земля, реквизит, светящиеся элементы (`glow=`). Блок — `soulscraft:<моб>_trophy` с `facing` |
| `figure` | коробка фигурки, пиксели от центра низа блока (модель смотрит на север): `lo`, `hi` и `floor` — высота, на которой стоит самая нижняя точка (ниже земли, если фигурка утоплена). `feet` — части, которые стоят на `floor` (сорокопут на ветке: хвост ниже лап) |
| `turn` | поворот фигурки от «лицом к табличке», градусы |
| `light` | свет блока 0..15 |
| `particles` | что пускает блок: тип из `PARTICLES`, `every` — в среднем тиков между двумя, `box` — коробка в пикселях модели блока |
| `text` | что за сцена, для витрины и подсказок |

Свои типы частиц — `PARTICLES` в том же файле: имя, цвет, форма спрайта (`soft`, `core`, `dot`, `ring`) и `behaviour` в формате `horizon:behaviour` движка (`velocity`, `velocity_jitter`, `gravity`, `friction`, `lifetime`, `size`, `alpha`). `build_blocks.py` пишет `assets/soulscraft/particles/<тип>.json` и спрайт `textures/particle/<тип>.png` (8×8), витрина получает их в `blocks.js` (`particles`).

Фигурка вписывается так: точки рига на каждом тике клипа (с предметами в гнёздах), повёрнутые на `yaw`; один масштаб и один сдвиг на весь клип: самая нижняя точка (или нижняя точка `feet`) — на `floor`, по x и z — в середине коробки. Масштаб не больше 1.

**Файл трофея** (`format: soulscraft-trophy`, `version: 2`):

| Поле | Что это |
| --- | --- |
| `head.parts` | части головы в формате `rig.json` (`name, parent, pivot, rotation, cubes`, UV в текстуре моба). У верхней части `parent: null`, а `pivot` и `rotation` — её место в кадре модели (абсолютные). Дети — как в риге |
| `head.texture` | та же текстура, что у моба |
| `head.icon` | `[часть, куб]` — главный куб головы: по его центру предмет-голова садится на голову игрока |
| `head.floor`, `head.wall` | `scale`, `offset` (пиксели), `yaw` (градусы) |
| `diorama.block` | блок диорамы, `soulscraft:<моб>_trophy` |
| `diorama.clip`, `ticks`, `loop` | клип позы, его длина и то, что он по кругу |
| `diorama.flags` | флаги состояния, включённые у фигурки |
| `diorama.scale`, `offset`, `yaw` | масштаб, сдвиг (пиксели) и поворот фигурки |
| `diorama.light` | свет блока |
| `diorama.text` | описание сцены |
| `diorama.plaque` | `from`, `to` — латунная табличка в пикселях модели блока, лицом на север |
| `diorama.particles` | `[{type, every, box: {from, to}}]`: тип частицы, в среднем тиков между двумя, коробка в пикселях модели блока, лицом на север |

Как рисует мод (каждая операция `BlockEntityDraw` умножает стек справа):

```text
translate(0.5, 0, 0.5)                      центр низа блока
rotate_about(y, turn)                       голова на полу: -22,5 × rotation; на стене и диорама: -facing_y
translate(offset / 16)
rotate_about(y, yaw)                        180 + поворот сцены: фигурка смотрит туда же, куда табличка
scale(scale)
scale(1, -1, -1); translate(0, -1.501, 0)   кадр модели, как у моба
части рига: у фигурки — дорожки клипа на тике (game_time + фаза) % ticks плюс partial,
части с флагом — по flags; у головы — части head.parts в покое; предметы в гнёздах — как у моба
```

Частицы: серверный тик block entity, каждый тик для каждой строки с шансом `1 / every` — одна частица в случайной точке коробки, повёрнутой по `facing` (`send_particles(тип, None, точка, [0, 0, 0], 0, 0)`; исследование [trophy-effects.md](../../docs/research/trophy-effects.md)).

Проверки:

- Сборка: фигурка на каждом тике клипа не выходит из блока и из коробки сцены и не даёт совпадающих граней с моделью диорамы; голова на полу и на стене не выходит из блока и не даёт совпадающих граней с полом и стеной. Модели диорам проверяются на совпадающие грани, как все блоки.
- Громила: сборка падает, если на любом тике клипа `trophy` (между ключами тоже) молот входит в тело, руки, голову или рога (`clash` в `mobs/brute.py`, коробки кубов и элементов молота, кроме рукояти в правом кулаке) или если боёк не лежит на правом плече (`rests_on_shoulder`: опущенный на 0,4 пикселя, он входит только в наплечье).
- `selfcheck.py`: читает готовые файлы трофеев и по цепочке выше, только из чисел JSON, проверяет, что фигурка внутри блока на каждом тике при каждом `facing`, голова — при всех 16 `rotation` и 4 `facing`; части головы — те же, что в риге; блок, клип и его длина, флаги, свет 0..15, файлы частиц и коробки в пределах блока.
- `preview.py -- trophies` (из `mobs.blend`) ставит части моба туда, куда их поставит мод, тоже только по числам JSON: `previews/head_<моб>_floor.png`, `_floor_r10`, `_wall`; `trophy_<моб>.png` (в три четверти спереди слева), `_front`, `_far` (блок такого размера, как на экране с 3 блоков), `_night` (луна и свет блока: видно свечение), `_figure` (фигурка крупно), `_t40` (середина клипа); листы `head_sheet.png`, `trophy_sheet.png`, `trophy_front_sheet.png`, `trophy_far_sheet.png`, `trophy_night_sheet.png`, `trophy_figure_sheet.png`. Частиц на картинках Blender нет, их показывает витрина.

## Оси: Blender и игра

| Что | Blender | Игра |
| --- | --- | --- |
| Единица | 1 = блок | пиксель |
| Вверх | +Z | −Y |
| Перед моба | −Y | −Z |
| Начало | ноги, Z = 0 | 24,016 пикселя над ногами |

- Часть — объект Blender `<моб>:<часть>`, origin — точка поворота, родитель — родительская часть. Часть без кубов (`root`) — пустышка.
- Ключи пишутся в Euler `XZY` Blender: `(x, z, −y)` от углов игры. Это тот же поворот, что `Rz·Ry·Rx` игры, поэтому Blender интерполирует ровно каналы игры.
- В `rig.json` углы не копируются: сборка берёт матрицу позы части на каждом тике, переводит в кадр игры (`K·M·Kᵀ`) и раскладывает в Z-Y-X.
- Масштаб части `(x, y, z)` игры — масштаб объекта Blender `(x, z, y)`; Blender масштабирует после поворота в кадре объекта, как `ModelPart`. В `rig.json` масштаб читается из каналов объекта, а поворот — из каналов положения и углов, поэтому у части с масштабом 0 поворот остаётся.
- Клип — слотовое действие (`Action`) Blender на дорожке NLA с именем клипа; метки фаз — маркеры действия. glTF выгружает дорожки NLA как анимации с теми же именами. Канал, который весь клип стоит на месте, экспортёр по умолчанию выбрасывает, даже если он не в покое (ноги латника в `idle`); сборка включает `export_optimize_animation_keep_anim_object`, и такой канал остаётся двумя ключами. Так в каждом клипе есть положение, поворот и масштаб каждой части.
- Превью предмета в руке — объект под гнездом с матрицей `Kᵀ · translate(t/16) · Rx·Ry·Rz · scale · translate(−0,5)` из `display` модели предмета (у спрайта — `display` родителя). В `assets/models/<моб>.glb` предмет не попадает: витрина собирает его из JSON модели предмета (спрайт — из его PNG тем же выдавливанием) по той же цепочке. В `assets/site/<моб>.glb` он есть (см. «Модели для сайта»).

## Файлы

- `build.py` — сборка: находит мобов, строит сцены, проверяет метки, выгружает всё.
- `rig.py` — части, кубы, гнёзда, клипы, перевод осей, раскладка листа, объекты Blender, `rig.json`.
- `paint.py` — палитры, шум, заливка граней, детали, запись PNG.
- `items.py` — модели предметов: спрайты и их выдавливание, элементы, `display`; броня ванильной формы, превью предмета в руке.
- `effects.py` — значки эффектов (`mob_effect`) 18×18: картой пикселей и палитрой, как спрайты; движок берёт их из `assets/soulscraft/textures/mob_effect/<эффект>.png` и без файла рисует «нет текстуры».
- `embed.py` — данные для витрины (значки эффектов — `SC.effectIcon` в `items.js`, их показывает мувсет).
- `site_models.py` — модели для сайта в `assets/site/`: моб с предметами в руках, копия алтаря, проверка размеров (не `site.py`: это имя занято стандартной библиотекой Python).
- `zfight.py` — поиск совпадающих граней, сборка падает на любой паре.
- `selfcheck.py` — проверка перевода осей, меча латника, поиска граней, файлов блоков и трофеев.
- `trophies.py` — головы и диорамы: части головы, вписывание фигурки в сцену на всех тиках клипа `trophy`, проверки, `<моб>.trophy.json`.
- `preview.py` — картинки в `previews/` (мобы; с `-- blocks` — блоки и уровни алтаря; с `-- site` — `site/preview.webp`).
- `blocks.py` — блоки: текстуры, элементы, модели, состояния, постройки, проверки движка, меши Blender.
- `build_blocks.py` — сборка блоков: файлы игры, `blocks.blend`, glb для витрины, реестр `blocks.js`.
- `blocks/altar.py` — алтарь: ядро, подставка, плита, гнездо, колонна, жаровня, обелиск, четыре уровня, горны ступеней 1–4 (Гнилой, мертвецов, бури, бездны), осколок души и книга охотника. Уровни, гнёзда и знамёна берёт из [data/altar.json](../../data/altar.json).
- `blocks/altar_banners.py` — двенадцать знамён-модификаторов со своими эмблемами.
- `blocks/dioramas.py` — диорамы семи мобов: общая подставка, сцены, свет блока, частицы (`SCENES`) и свои типы частиц (`PARTICLES`).
- `blocks/trophies.py` — блоки голов всех мобов со значками.
- `blocks/rewards.py` — спрайты предметов ступеней: Клинок латника, Молот громилы (`brute_maul_sprite`: так молот видит игрок, в руке громилы остаётся объёмная модель) и Сердце бездны. Блоков нет.
- `mobs/<моб>.py` — семь мобов первого среза: `revenant`, `stalker`, `marksman`, `brute`, `shrike`, `lurker`, `bog_slime`, с оружием и добычей.
- `mobs/_player.py` — фигура игрока для сцен витрины (с клипом прыжка, высоту прыжка даёт сцена, и клипом `place` — положить предмет перед собой).
- `mobs/_shelter.py`, `mobs/_brute_wall.py`, `mobs/_brute_wave.py` — реквизит сцен: навес, стена тарана, ударная волна.
- `mobs/_zombie.py` — простой зомби из кубов для сцены призыва на алтаре (своя текстура, не ванильная).

Текстуры и модели Minecraft сюда не копируются.
