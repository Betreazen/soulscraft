# Риги мобов для игры

`<моб>.rig.json` — модель и анимации моба в том виде, в каком их рисует мод: дерево `ModelPart`, кубы с box UV, гнёзда и клипы по тикам. Файлы генерирует `assets/models/build.py`, руками не правятся. Как пересобрать — [assets/models/README.md](../models/README.md).

Рядом лежит `<моб>.trophy.json` (версия 2): голова моба (части этого рига) и его диорама — блок, клип позы `trophy` этого рига, масштаб, сдвиг и поворот фигурки, флаги состояния, свет блока, частицы. Формат и цепочка отрисовки — [assets/models/README.md](../models/README.md), раздел «Трофеи».

## Кадр и единицы

Всё в пространстве модели моба игры, в пикселях (1/16 блока):

| Ось | Куда |
| --- | --- |
| +x | левая сторона моба |
| +y | вниз |
| −z | куда смотрит моб |
| начало | 24,016 пикселя над ногами (`translate(0, -1.501, 0)`) |

Повороты в радианах, порядок как у `ModelPart`: сначала Z, потом Y, потом X (матрица `Rz·Ry·Rx`). Масштаб части — после поворота, по её осям, как `xScale`, `yScale`, `zScale` у `ModelPart`; дети его наследуют. Точка Blender `(X, Y, Z)` в блоках переходит в `(16X, 24,016 − 16Z, 16Y)`.

## Версии

| Версия | Что изменилось |
| --- | --- |
| 1 | первая: строка дорожки — 6 чисел |
| 2 | масштаб частей: строка дорожки — 6 или 9 чисел; поле `parts[].state` |

## Поля

```json
{
 "format": "soulscraft-rig", "version": 2, "id": "brute",
 "texture": {"sprite": "soulscraft:entity/revenant", "width": 64, "height": 64},
 "parts": [{"name": "body", "parent": "root", "pivot": [0, -12, 0], "rotation": [0, 0, 0],
            "cubes": [{"origin": [-4, -12, -2], "size": [8, 7, 4], "uv": [0, 17], "inflate": 0.75}]},
           {"name": "eyes_rage", "parent": "head", "state": "rage", "…": "…"}],
 "sockets": [{"name": "socket_hand_r", "parent": "arm_r", "offset": [-1, 10, -2],
              "rotate": [["x", -90], ["y", 180]], "item": "soulscraft:rusty_sword", "display": "thirdperson_righthand"}],
 "clips": {"attack_slash": {"ticks": 24, "loop": false,
           "markers": {"windup": 0, "hit": 10, "recover": 12, "end": 24},
           "tracks": {"arm_r": [[-5, -10, 0, -0.2094, -0.1396, 0.2094], "…по строке на тик…"],
                      "lure": [[0, -3, 0, 0, 0, 0, 1, 1, 1], "…с масштабом: 9 чисел…"]}}}
}
```

| Поле | Что это |
| --- | --- |
| `texture` | спрайт атласа и размер листа для box UV (`LayerDefinition.create(mesh, w, h)`) |
| `parts` | части в порядке «родитель раньше детей» |
| `parts[].pivot` | `PartPose.offset`: точка поворота относительно точки родителя, в кадре родителя; у корня — от начала модели |
| `parts[].rotation` | поворот покоя (x, y, z) |
| `parts[].state` | необязательно: часть видна, только пока у моба включён флаг состояния (`"rage"`), или только пока он выключен (`"!lit"`). Скрытая часть скрывает и своих детей, как `ModelPart.visible`. Флаги ставит мод (громила: `rage` ниже 30% здоровья) |
| `parts[].cubes` | `addBox(origin, size)` в кадре части; `uv` — `texOffs`; `inflate` — `CubeDeformation` (число или три); `mirror` — `CubeListBuilder.mirror()`; `glow` — рисовать с `draw.light = 0xF0F0`; `faces` — если граней меньше шести |
| `sockets` | гнёзда: `offset` в пикселях от точки родителя, затем повороты `rotate` по порядку (каждый умножает стек справа). `item` и `display` — что моб держит и каким контекстом рисовать |
| `clips` | клипы по имени |
| `clips.*.ticks` | длина в тиках; кадров `ticks + 1`, от 0 до конца включительно |
| `clips.*.loop` | клип по кругу (`idle`, `walk`, `block`, `circle_strafe`): последний кадр равен первому |
| `clips.*.markers` | метки фаз атаки в тиках, те же, что в `data/mobs.json` |
| `clips.*.tracks` | для каждой части, которая двигается в клипе: строка на тик `[x, y, z, xRot, yRot, zRot]` — полные значения полей `ModelPart` (точка поворота и углы), не прибавка. Если часть в клипе хоть на одном тике масштабируется, у всех её строк ещё три числа `xScale, yScale, zScale`; без них масштаб 1. Масштаб 0 прячет часть (погасшая приманка удильщика, блик арбалетчика вне прицела). Части без дорожки весь клип стоят в покое |

Углы в дорожке идут непрерывно: соседние тики не прыгают через ±π, поэтому их можно смешивать линейно.

## Как играть клип в моде

```text
каждый кадр:   t = (game_time - start) + partial       тики от начала клипа
               i = floor(t), f = t - i                 у loop: i по модулю ticks
               для каждой части с дорожкой: поле = lerp(track[i], track[i + 1], f)
                 (у строки из 6 чисел масштаб 1)
               остальные части: pivot и rotation покоя, масштаб 1
               часть с state: visible = флаг моба включён (или выключен для "!флаг")
```

- `walk` — один цикл шага. Игра крутит его по `walk_position` (у ванили период `2π / 0,6662` ≈ 9,43), а не по времени.
- Фаза атаки и тик её начала приходят с сервера (исследование [horizon-mob-models.md](../../docs/research/horizon-mob-models.md), 2.4). Удар наносится на тике `hit`.
- Предмет в руке: после цепочки частей до родителя гнезда — `translate(offset / 16)`, повороты `rotate`, затем `native_draw_item(…, ThirdPersonRightHand, …)`. Он применит `display.thirdperson_righthand` модели предмета (рецепт 3.4 исследования).

## Проверка

`assets/models/selfcheck.py` ставит точки двумя путями: мировыми матрицами Blender и цепочкой игры только по числам из `rig.json`. Сравнивает три вложенные части с поворотом по всем трём осям (статично и в клипе, средняя ещё и с неравным масштабом), гнездо и предмет, а также собранного латника: гнездо и рукоять меча на каждом тике каждого клипа.
