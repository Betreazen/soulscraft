Спецификации: [09-trophies.md](../docs/design/09-trophies.md), [06-altar.md](../docs/design/06-altar.md) («Модификаторы», «Награда»), гипотеза Г10 в [03-hypotheses.md](../docs/design/03-hypotheses.md). Числа — `data/trophies.json`, `data/altar.json`, `data/mobs.json` (`kin`, `loot`); все — гипотезы до плейтеста. Учащённый спавн — отдельный файл [p4-spawn.md](p4-spawn.md).

Пометки: **[И]** проверено в исходниках движка (`SRC` = Horizon `7e4e421`, пути от `crates/horizon-client/src/`), **[Д]** документация движка, **[П]** проверено в игре (самотест или бот), без пометки — решение кода.

## Что работает

### Награда за победу

- Правила — крейт `soulscraft_rules::event::rewards`, сервер бросает предметы над ядром (`event.rs`, `reward`). Знамёна берутся те, что стояли при старте ивента (`plan.effects`), а не в конце.
- **Головы:** одна гарантирована, +1 за каждое знамя «сложнее», −1 за «проще», не меньше одной. Голова моба SoulsCraft — блок `soulscraft:<моб>_head`; ванильного моба — его ванильная голова (зомби — `zombie_head`, как в спецификации тестового ивента).
- **Части брони:** у каждой части из `loot` мобов SoulsCraft в ивенте шанс `0,3 × множитель`. Множитель знамён `1 + 0,25 · (сложнее − проще)`, не меньше 0 (`drops.banner_step`, предложение): два «сложнее» — 45%, два «проще» — 15%. У зомби частей брони нет.
- **Диорама:** только на алтаре уровня 3 и выше, одного из мобов SoulsCraft в ивенте. У ванильного зомби диорамы нет, поэтому чистый тестовый ивент диораму не даёт — её приносит знамя рода (ниже) или ивент с мобами SoulsCraft.
- Случайность — свой поток ивента (`Overrides::seed` в самотесте): то, что упало, совпадает с тем, что выбрасывают правила с тем же зерном [П] `reward_seeded_win`.

### Знамёна меняют ивент

- Тяжесть/милость (± 0,15 P), орда/затишье (± 25% врагов), спешка/отдых (передышка − 10 / + 15 с), стойкость (+ 50% здоровья алтаря) — были в плане с итерации 2 (`event::plan`), теперь проверены вместе с наградой.
- **Знамя рода** (новое): доля `kin_share` = 25% слотов каждой волны (кроме знаменосца; округлённо, не меньше одного) становится мобами SoulsCraft этого рода — последние слоты, бронированные зомби остаются; рода по очереди по числу знамён, мобы рода — по очереди, слабые (`tier_p`) раньше; элитный громила и только водный удильщик в волну не идут. Знамёна складываются, всего не больше всех слотов. Это предложение кода (`altar.json` `kin_rule`): «учащает группу» на зомби-ивенте иначе ничего бы не меняло.
- Род мобов — `data/mobs.json` `kin` (обязательное поле): нежить — латник, арбалетчик, громила, **сорокопут** (ровно мобы с `undead: true`, файл иначе не читается); звери — ловчий, удильщик; слизни — слизь; летучие — сорокопут; водные — удильщик, слизь. Кроме нежити — предложение.
- Меню ядра показывает сумму: строки силы, врагов, передышки, здоровья, «род: нежить — 25% волны и чаще в спавне», «трофеи: сложнее N, проще M (голов ±K)» и строку учащённого спавна.

### Трофеи в мире

Блоки — из файлов Blender (`assets/soulscraft/blockstates|models`), описания блоков — `mod/sync.ps1`:

| Блок | Шаблон и состояния | Что ещё |
| --- | --- | --- |
| `<моб>_head_stand` (после патча; до него `<моб>_head`) | `minecraft:stone`, своё `rotation` 0..15, рамка ванильной головы | ставит его предмет `<моб>_head` (`place_block`); предмет носится на голове (`minecraft:equippable` `slot: head`, рисуется по `display.head` модели предмета) |
| `<моб>_head_mount` (до патча `<моб>_wall_head`) | `minecraft:stone`, `facing`, рамки ванильной настенной головы, без предмета | роняет голову |
| `<моб>_trophy` | `minecraft:stone`, `facing`, `light` из файла трофея, `occludes: false` | столкновение — только подставка (3 пикселя), рамка — по модели |

- Голова и фигурка рисуются block entity (`trophy_client.rs`) тем же ригом и текстурой, что моб, по цепочке файла трофея. Голова неподвижна и сохраняется `keep()`; фигурка дышит клипом `trophy` по `game_time + partial` со сдвигом фазы от места блока и `keep()` не зовёт. Светящиеся кубы — на полном свете.
- Поворот при установке — хук `state_for_placement`: голова — к игроку в 16 шагах, как `SkullBlock` (`(yaw + 180) · 16 / 360`), диорама — табличкой к игроку [И] `game.rs:1659-1669` (только `native_authoritative`, без `mods()`).
- На стену: голова в руке по боковой грани — `<моб>_wall_head` лицом от стены (`right_click_block` с гранью). Своего «стенного» предмета у шаблонов голов мода нет: `wall_block` движок принимает только у табличек [И] `horizon-mods/src/content.rs:1182-1190`, а предмет блока на шаблоне `skeleton_skull` ставил бы на стену ванильный череп скелета (его `wallBlock` не переименовывается) [И] `mod_content.rs:1385-1394`.
- Частицы диорамы — на сервере: каждый тик по каждой строке файла с шансом `1 / every` одна частица своего типа `soulscraft:*` в случайной точке коробки, повёрнутой по `facing`; `count 0`, `speed 0` — движение задаёт `horizon:behaviour` типа. Отправка — `GameLevel::native_send_particles` [И] `native_hooks.rs:9928-9963` (уровень за стабильным `LevelWriteHost::send_particles`, API 103), из тика уровня через `Game::with_level` [И] `game.rs:4716-4719`; уровень на месте — тот, чей тик [И] `levels.rs:559-561`. Хук тика block entity игры не получает [И] `native_hooks.rs:3536`, поэтому он только записывает, где диорама.
- Частота в самотесте [П] `trophy_particles`: латник (туман раз в 6, огоньки раз в 12) за 200 тиков — около 50.
- Части брони — предметы на шаблоне `minecraft:bone`, по одному в стопке, без очков брони (декоративные): шлемы и капюшоны с `equippable` `slot: head` рисуются моделью предмета на голове; нагрудник — `slot: chest`, `asset_id: soulscraft:rusty` (слой `humanoid`, `assets/soulscraft/equipment/rusty.json`).
- Своя вкладка творческого режима «SoulsCraft: трофеи».

## Чего нет и что не проверено

- **Табличка:** `native_draw_text` всё ещё без номера API (`@API:draw_text@`) [И] `native_block_entity_draw.rs:582`. Табличка остаётся латунью; имя — в названии предмета.
- **Манекены** брони на этом коммите не рисуют — известный пробел движка; стойка для брони — проверяется в раунде с клиентом.
- **Голова в слоте интерфейса** — плоский значок с лица головы (запасной вариант 09-trophies.md); своей отрисовки головы в слоте нет.
- **Частицы на клиенте** — когда `add_particle` и `client_tick_*` получат номера, перенести их туда, без сети.
- **Головы в обычном мире** (1% и 3%) и узел PCT «Охотник за головами» — не в этой итерации.
