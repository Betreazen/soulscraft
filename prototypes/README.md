Первая итерация кода собрала П1–П3 вместе и инструменты П5: семь мобов первого среза на общем стенде, их атаки по тикам из `data/mobs.json`, рост от силы P и набор для быстрых проверок. Код и хуки — [../mod/README.md](../mod/README.md).

## Как гонять

Проверки идут по уровням, от быстрых к медленным (README стенда, «Быстрые проверки»):

```powershell
cargo test                                   # 1. крейт rules: логика, секунды
cd "C:\Claude code projects\horizon-joint-dev"
.\joint.ps1 stage -Mod soulscraft
.\joint.ps1 server                           # серверный движок со всеми модами стенда
.\joint.ps1 check -Owner "soulscraft agent"  # 2. самотест без клиента: selftest\soulscraft.json
.\joint.ps1 client                           # клиент нужен только для вида
.\joint.ps1 open; .\joint.ps1 serve -Owner "soulscraft agent"
.\prototypes\shots.ps1 -Mob revenant         # 3. бот sc_a, скриншоты по фазам, тики из лога
.\prototypes\check-book.ps1                  # книга охотника в окне: evidence\book\
.\prototypes\check-round11.ps1 -Parts heads  # надетые головы, камера — второй бот sc_b: evidence\round11\
.\prototypes\check-vanilla.ps1               # замахи ванильных мобов через /sc force: evidence\vanilla\
.\prototypes\check-final.ps1 -Only brute_wave,record  # 0.7.0: 11 сцен (латник … ивент, запись LetsCam), без -Only все: evidence\final\
.\prototypes\check-final.ps1 -Version native-8f83e5c-<ключ> -Export soulscraft-N  # 0.8.0: те же сцены на Mod API (сервер Linux в horizon-linux-dev), без записи LetsCam
.\prototypes\tune.ps1                        # числа из data/mobs.json на живой сервер (/sc reload)
.\prototypes\p5-world.ps1 init               # П5: свой сервер и мир без естественного спавна (раз)
.\prototypes\p5-bench.ps1                    # П5, только на тихом ПК; heavy.lock берёт сам
```

## Команды оператора `/sc`

| Команда | Что делает |
| --- | --- |
| `/sc spawn <моб> [P] [число]` | мобы в 5 блоках перед игроком; без P — `/sc p` или 0 |
| `/sc p <0..1\|off>` | сила P для новых спавнов вместо настоящей |
| `/sc reload` | перечитать `config/soulscraft/mobs.json` без пересборки: новые тики и числа со следующей атаки |
| `/sc debug on\|off` | подпись фазы над каждым мобом (`overhead:hold 12`, цвет по фазе); мобы видят игроков в творческом режиме |
| `/sc slowmo <1..20\|off>` | `/tick rate`; `/sc freeze [off]` — `/tick freeze` |
| `/sc arena` | плоская освещённая арена 31×31 на y 100 в центре участка SoulsCraft (−500, 500): бассейн для удильщика, стена для тарана |
| `/sc wave start\|next\|stop` | заглушка тестового ивента: волны зомби из `events[0]` кольцом вокруг игрока, передышка после волны |
| `/sc force <атака>` | ближайший моб SoulsCraft начинает эту атаку сейчас; если его нет в 16 блоках — ближайший принятый ванильный моб с этим приёмом |
| `/sc clear`, `/sc info` | убрать мобов SoulsCraft рядом; что загружено |
| `/sc bench [N] [моб\|mixed]`, `/sc cost start\|stop` | П5: кольцо из N латников (или мобов одного вида, или всех семи по очереди); замер стоимости |
| `/sc power` | сила P каждого игрока по частям: дерево `T` из сводки PCT и снаряжение `G` (Г1) |
| `/sc pct <игрок> <ближний> <стрельба> <защита>\|off` | тестовая сводка `pct:summary` боту, как её пишет PCT (уровни из 75); `off` убирает |
| `/sc altar <0..4> [banners]` | алтарь этого уровня в 6 блоках перед игроком на каменном полу (с `banners` — образцовые знамёна в гнёздах, `data/altar.json` `sample_banners`); 0 — только ядро и подставка |
| `/sc horn` | Гнилой горн в инвентарь |
| `/sc book <игрок> [reset\|open\|meet <моб>\|kill <моб> [n]]` | книга охотника игрока: ступени всех записей; с начала; открыть окно; встреча или убийства как настоящие (со строкой над панелью) |
| `/sc event start\|stop` | тестовый ивент на ближайшем алтаре в 32 блоках (игроки в зоне — участники) или его остановка (стены возвращаются) |

Из консоли сервера (`horizon-server cmd "sc …"`) команды тоже работают, точка — центр арены.

Утром 13.11 ожидание чужого стенда (`try/wait for another try`, «Another native build») и взаимная блокировка двух `try` до исправления стенда (8ccc1a5) заняли около часа — это не время сборки SoulsCraft.

Что тормозит и что SoulsCraft может сделать:

- **Чужие сборки.** Больше половины времени раунда — ожидание сборок другого набора модов (отдельный instance PCT): общий `native\stage` пересобирает `horizon-client-lib` и `horizon-client` при каждой смене набора. Это вопрос стенда, не кода мода.
- **`horizon-client-lib`.** Хелпер `register_goals` SoulsCraft компилируется в библиотеку клиента (функция там, `mobs/ai.rs:464`), как и `living_fall` RustCraft, поэтому смена этого хелпера пересобирает её. Хелпер в несколько строк и меняться не должен; вся логика — в крейте `rules`, который собирается за секунды и в разбивке не виден.
- **Самотест** занимает 2–2,5 с из ~50 с проверки: остальное — запуск сервера на свежем мире.
- **Клиент** нужен только для вида. Логика, числа и тайминги проверяются раундом без клиента (`round` без `-WithClient`).

Итерация 3 (14.11): `try` 19:13 — 742 с (сервер 207 с, запуск сервера на свежем мире 289 с, самотест SoulsCraft 9,0 с, 58 сценариев); клиент 19:25 — 911 с (сборка 772 с с обходом через `fdc87ae`). Ожидание 13.11: метка обслуживания на публикацию pack-6 держала все сборки с 16:57 до 18:27.
