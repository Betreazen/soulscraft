## Коротко

1. Своего `animateTick` у блока мода нет. Ванильный `ClientLevel.animateTick` выбирает поведение по имени блока, а не по шаблону. Блок мода на шаблоне факела или костра частиц не даёт. Клиентского тика block entity тоже нет: `native_block_entity_tick` идёт только на сервере.
2. Сейчас (стабильный API) частицы можно пускать двумя путями. Первый: сервер. Тик block entity мода и `send_particles(options, state, at, spread, speed, count)`. Тип любой ванильный (кроме item/trail/vibration) или свой `soulscraft:*` из JSON. Уходит игрокам в 32 блоках. Второй: клиент. Хук `tick` в окне и хелпер `flame_particle(at, soul)`. Он даёт только `flame` или `soul_fire_flame`.
3. Клиентский хелпер на любой тип уже написан: `add_particle(&ParticleOptions, at, velocity) -> bool`. Но он ожидающий, как и хуки `client_tick_pre/post`. Когда получит номер, частицы диорамы лучше перенести на клиент.
4. Все запрошенные ванильные типы в Horizon есть, включая `firefly`, `white_smoke`, `dust` с цветом и размером. Своего типа для грязи у ванили нет. `bubble` и `bubble_column_up` гибнут вне настоящей воды, в диораме они не живут. `bubble_pop` живёт в воздухе.
5. Частицы смешиваются по альфе (вырез ниже 0.1). Полупрозрачный слой (дым костра, облако, души, светлячки, `end_rod`) рисуется после полупрозрачного ландшафта, при «улучшенной прозрачности» через OIT. Свет — блочный и небесный свет блока, где частица. У огня свет растёт с возрастом, `end_rod` светит всегда, светлячок светит сам. Предел — 16384 частицы на всё, с 12288 новые отсеиваются. Рождаются частицы только в 32 блоках от камеры.
6. Отрисовка block entity получает `draw.partial` и `draw.game_time`. Её зовут каждый кадр, если мод не вызвал `draw.keep()`. `keep()` замораживает рисунок: хук больше не зовут, пока не сменятся состояние, данные block entity, свет или ресурсы. Значит, трофей с медленной анимацией позы `keep()` не вызывает.
7. Свет блока задаёт поле `"light": 0..15` в `properties` объявления блока. Оно одно на все состояния. Разный свет по состояниям бывает, только если `light` не задан: тогда он копируется из состояний шаблона. Менять его на ходу можно только сменой состояния блока с сервера.
8. Рамка отсечения block entity по умолчанию — блок плюс блок запаса со всех сторон: от −1 до 2. Выступ на 1–2 пикселя ничего не требует. Шире — хук `native_block_entity_render_bounding_box`.
9. Текст на табличке: `native_draw_text(draw, text, at, color, glowing, outline)` есть, но тоже ожидающий. Стабильный обходной путь — свои глифы спрайтом через `native_draw_quad`.

## 1. Как блок или block entity выпускает частицы

### 1.1 Ванильный `animateTick` и блоки мода

- Клиент раз в тик делает 667 случайных проб в радиусе 16 и 667 в радиусе 32 вокруг игрока — [И] `client/animate_tick.rs:571-580`. Вызов идёт из тика отрисовки окна — [И] `client/game/render_tick.rs:506`.
- Поведение блока выбирается по имени при загрузке таблиц: `classify(&s.name, …)` по каждому состоянию реестра — [И] `client/animate_tick.rs:330-336`. `classify` срезает только `minecraft:` и сравнивает имя — [И] `client/animate_tick.rs:117-122`. Блок `soulscraft:trophy_diorama` на шаблоне `minecraft:torch` получает `Animate::None`. Шаблон даёт блоку класс поведения, но не частицы animateTick.
- Хука мода в этой петле нет. В `do_animate_tick` нет вызова `native_*` — [И] `client/animate_tick.rs:581-640`, поиск `native_` по `render_tick.rs` нашёл только туман.
- Побочный эффект [И, `client/animate_tick.rs:167, 224, 251-253`]: правила с суффиксом срабатывают и на имена модов. Блок `soulscraft:x_candle` со свойствами `lit=true` и `candles` пустит частицы свечи. Блок `soulscraft:x_concrete_powder` пустит пыль. Опираться на это не стоит: это случайность, её могут закрыть [П].
- Клиентского тика block entity нет. `native_block_entity_tick(&mut self, pos, entity)` — «A server tick of the block entity» — [И] `client/game/native_hooks.rs:3526-3538`. Тикает ли block entity, решает `native_block_entity_ticks(block, &mut ticks)` — [И] `native_hooks.rs:3315-3321`.

Отрисовка block entity `native_block_entity_submit` получает `&self` — [И] `native_hooks.rs:3607-3613`. Хелперы частиц берут `&mut self` — [И] `native_hooks.rs:10411`, `native_client_particles.rs:33`. Из отрисовки частицу не пустить [И]. Нужен отдельный хук с `&mut`: `tick` на клиенте или тик block entity на сервере.

### 1.3 Сигнатуры

```rust
// Сервер, тик block entity: Host уровня (LevelWriteHost)
fn send_particles(&mut self, options: &ParticleOptions, state: Option<BlockStateId>,
                  at: [f64; 3], spread: [f64; 3], speed: f64, count: i32) -> bool;

// Клиент, хук tick (только в окне): Host
fn flame_particle(&mut self, at: [f64; 3], soul: bool);
fn lit_block_name(&self, pos: [i32; 3]) -> Option<&str>;

// Клиент, ожидающий
fn add_particle(&mut self, options: &ParticleOptions, at: [f64; 3], velocity: [f64; 3]) -> bool;
```

- `send_particles` — [И] `client/mod_api.rs:1038-1047`. `flame_particle`, `lit_block_name` — [И] `native_hooks.rs:10398-10429`, в Host без префикса `native_` — [Д] `NM:5055-5058`.
- `ParticleOptions`: `simple(ParticleType)`, `dust(rgb, scale)` (размер зажат в 0.01..4), `dust_transition(from, to, scale)`, `colored(ty, rgba)`, `block(ty, sprite, tint)`, `named("ns:имя")` — [И] `render/particles.rs:69, 87-92, 123, 169-189`.
- `send_particles` на клиенте разворачивается как ванильный `sendParticles`. При `count = 0` одна частица ровно в `at` со скоростью `speed * spread`. При `count > 0` каждая частица в `at + gauss * spread`, скорость `gauss * speed` по каждой оси — [И] `render/particles.rs:1913-1938`. `spread` — это разброс по Гауссу, а не коробка: часть частиц вылетит за 2–3 `spread`.
- Сервер шлёт пакет игрокам ближе 32 блоков к точке (от центра блока игрока) — [И] `client/game/lan_particles.rs:668-676`. Свой тип мода получают только клиенты Horizon — [И] `lan_particles.rs:65-71`.
- `flame_particle` молча ничего не делает дальше 32 блоков от игрока (`> 1024.0` в квадрате), скорость фиксирована `[0, 0.01, 0]`, частота на совести мода — [И] `native_hooks.rs:10410-10428`.

### 1.4 Свой тип частицы из JSON

`assets/soulscraft/particles/<имя>.json`, текстуры как `particle/<текстура>` в атласе — [Д] `NM:1051`. Блок `horizon:behaviour` задаёт `velocity`, `velocity_jitter`, `gravity`, `friction`, `lifetime` (1..12000), `size: [начало, конец]` (полуширина в блоках, 0..16), `alpha: [начало, конец]`, `animation` — [Д] `NM:1053-1101`. Без `velocity` скорость случайная, и вызов задаёт только направление — [Д] `NM:1051, 1077-1079`. С `alpha` частица уходит в смешиваемый слой — [Д] `NM:1094`. Своего света у такого типа нет: поля яркости в `horizon:behaviour` нет, он освещается миром [Д, по списку полей]. Полная яркость только у компилируемого контроллера (`set_full_bright`) — [Д] `NM:108-110`.

## 3. Прозрачность, свет и цена частиц

- Все частицы идут конвейером сущностей `entity_pipeline` с альфа-смешением и записью глубины — [И] `render/gfx.rs:4081-4089`. Пиксели с альфой ниже 0.1 отрезаются — [И] `render/entity.wgsl:310`.
- Полупрозрачный слой (оверлей 15) рисуется после полупрозрачного ландшафта, иначе он закрыл бы стекло и воду — [И] `render/gfx.rs:11070-11082`, `render/gfx/entity_batch.rs:9-10, 63-64`. При включённой «улучшенной прозрачности» эти частицы идут через OIT — [И] `render/gfx/oit_features.rs:13`, условие `!oit_on` в `gfx.rs:11074`.
- Свет частицы — упакованный свет блока, где её центр, через кэш на 64 блока — [И] `render/particles.rs:1323-1337, 4858`. Режимы: мир, полный (`end_rod`, фейерверк), блочный 15 (`lava`, слеза), растущий с возрастом (огонь, `glow`), свой у светлячка — [И] `:1075-1093`.
- Спавн: дальше 32 блоков от камеры частица не создаётся, кроме типов `override_limiter` — [И] `render/particles.rs:1708-1732`, список `particle_type.rs:154-189`. Настройка «Частицы»: «меньше» срезает треть, «минимум» — почти всё — [И] `render/particles.rs:1744-1755`.
- Предел: 16384 частицы на движок. С 12288 новая частица принимается с вероятностью `((16384 − n) / 4096)²` — [И] `render/particles.rs:1299-1302, 3751-3760`.
- Отсечение при отрисовке: пирамида видимости по секциям и сферам, частица меньше полупикселя, загороженная ландшафтом — [И] `render/particles.rs:4745-4764, 1435-1445`.
- Частицы со столкновениями (дым, пыль, снежинка) упираются в формы столкновения блоков и останавливаются, когда вертикальное движение упёрлось — [И] `render/particles.rs:1020-1048`. Спавнить их внутри формы столкновения трофея нельзя [П].
- Цена одной частицы: тик на CPU и один квадрат в пакете сущностей [И, по коду тика и отрисовки]. Десятки частиц на диораму — малая доля предела [П].

## 4. Анимация в отрисовке block entity

- `BlockEntityDraw` несёт `partial: f32` (0..1) и `game_time: i64` («for animations»), а также `light` — [И] `client/game/native_block_entity_draw.rs:44-56`. Их заполняют перед каждым вызовом: `game_time: self.world.game_time`, `partial` кадра — [И] `:427-440`. Отдельно есть хелпер `native_clock() -> Option<NativeClock { game_time, day_time }>` — [И] `native_hooks.rs:11219-11228`, API 92.
- Вызов `native_block_entity_submit` идёт раз в кадр для каждого block entity мода в 64 блоках, чей чанк проявился и чья рамка в пирамиде видимости — [И] `native_hooks.rs:3595-3606`, петля `native_block_entity_draw.rs:443-536`.
- `draw.keep()` (API 94): рисунок сохраняется, и ни `submit`, ни хук рамки больше не вызываются, пока не сменятся состояние блока, данные block entity (ревизия), свет блока или атлас — [И] `native_block_entity_draw.rs:200-212`, ключ `:301-316`, проверка `:462-480`. Хранится, пока его рисуют, и ещё 100 тиков — [И] `:301-302, 340-363`. В документации прямо сказано: вызывать `keep`, только если рисунок не читает `partial`, `game_time` и ничего своего. Сохранённая геометрия стоит на месте — [И] `:203-210`.
- Вывод [И, по коду]: `keep` нельзя включать по дальности. Если трофей сохранён, мод больше не узнает, что игрок подошёл.
- `draw.spin(axis, pivot, degrees_per_tick, phase)` и `still()` крутят часть с постоянной скоростью от `game_time + partial`, в том числе под `keep` — [И] `native_block_entity_draw.rs:213-243, 79-89`. Но это ожидающий API (`@API:spinning_geometry@`, `frag/spinning_geometry.json`). Для диорамы он годится разве что на вращающуюся мелочь.
- Цена [И]: без `keep` мод каждый кадр строит вершины на CPU. С `keep` вершины всё равно копируются каждый кадр со сдвигом к камере (`native_block_entity_draw.rs:466-476`), но код мода не работает. Сколько стоит 20 анимированных диорам, надо мерить ([09-trophies.md](../design/09-trophies.md), «Что проверить», п. 3) [П].

## 5. Свет блока

- Поле: `"properties": { "light": 3 }` в `data/soulscraft/horizon/block/<блок>.json` — [Д] `docs/mods.md:117-122`, `docs/modpacks.md:213-218`. Тип `Option<u8>`, больше 15 — ошибка загрузки — [И] `crates/horizon-mods/src/content.rs:80-82, 1118-1120`.
- Применение: строка каждого состояния блока — копия строки состояния шаблона, затем `light` пишется в `emission` — [И] `client/mod_content.rs:1246-1263, 1329-1331`. Значит, `light` один на все состояния, в том числе на свои `state_properties`. Если `light` не задан, каждое состояние берёт свет соответствующего состояния шаблона [И, там же]. Свет по своему свойству `ground` поэтому не сделать [И].
- Менять на ходу можно только сменой состояния блока с сервера (`set_block_property`, API 33 — [И] `native_hooks.rs:9963-9996`), и только если свет различается у состояний шаблона. Пример: шаблон со свойством `lit` [П]. Шаблон приносит и свой класс поведения, это надо проверять для каждого.
- Свет освещает окрестность как ванильный: таблица `emission` — это та, что читает `native_lit_block_name` (`facts.emission > 0`) — [И] `native_hooks.rs:10398-10409` [П: что освещение мира берёт ту же таблицу, видно по названию поля, но сам движок света не открывался].
- Фигурку в block entity освещает свет её же клетки: `vertex_light(self.world.light(pos))` — [И] `native_block_entity_draw.rs:458`. У шаблона, который загораживает (`stone`), свет внутри клетки — только его собственный, и фигурка будет тёмной [П, по ванили]. `"occludes": false` пропускает свет, ослабляя его на 1 — [Д] `docs/mods.md:137-141`.
- Свечение без света в мире: `draw.light = 0xF0F0` для частей фигурки, `light_emission` на гранях элементов JSON-модели подставки — см. horizon-mob-models.md, 1.4. Мигающий цветной свет — `native_visuals` (не игровой свет, не дальше 32 блоков, 8 огней на мод, всего 16) — [Д] `NM:398-408`.

## 6. Рамка отсечения block entity

- По умолчанию `[-1, -1, -1, 2, 2, 2]`: блок и блок запаса — [И] `native_block_entity_draw.rs:28-30`. Выступ на 1–2 пикселя внутри неё.
- Шире: хук `native_block_entity_render_bounding_box(pos, block, state, entity, &mut bounds)`, API 71. Бесконечное значение — никогда не отсекать — [И] `native_hooks.rs:3624-3646`, `native_block_entity_draw.rs:32-42`. Хук зовут раз в кадр, но не для сохранённых через `keep` — [И] `:462-488`.
- Дальность 64 блока жёсткая (`VIEW_DISTANCE`), строго ближе — [И] `native_block_entity_draw.rs:26-27, 444-448`. Отсечения по загороженности для block entity нет, только рамка — [И] `:415-420`.
- Сама модель блока в чанке: элемент JSON от −16 до 32 текселей — horizon-mob-models.md, 1.1.

## 7. Текст на табличке

`native_draw_text(draw, &Text, at: [f32; 2], color: u32, glowing: bool, outline: u32) -> f32` рисует строку как табличка: единица — пиксель шрифта, `draw.scale([1/64, -1/64, 1/64])` перед вызовом, возвращает ширину для центрирования — [И] `native_block_entity_draw.rs:571-628`. Ожидающий (`@API:draw_text@`, `frag/draw_text.json`). Пока номера нет, обходной путь — свой спрайт с буквами и `native_draw_quad` (API 71) [П]. Под `keep` текст сохраняется и перерисовывается при сбросе шрифта — [И] `:309-315`.

## 8. Что из этого следует для диорамы [П]

### 8.1 Откуда пускать частицы

- Сейчас: на сервере. `native_block_entity_ticks` включает тик для блоков диорам (`<моб>_trophy`), тик block entity с шансом на тик зовёт `send_particles`. Работает в одиночке и на сервере, частицы видны всем, игроки дальше 32 блоков пакета не получают.
- Позицию лучше ставить самим: `count = 0`, точка случайная в коробке, скорость `speed * spread`. При `count > 0` разброс гауссов, и частицы вылетают за рамку.
- Для эффектов в масштабе фигурки (0.2–0.6 от моба) ванильные частицы крупны: снежинка 3–6 пикселей, огонь 3–6. Почти для всех эффектов лучше свои типы `soulscraft:*` с `horizon:behaviour`: точный размер, скорость, жизнь и затухание.
- Позже: когда `add_particle` и `client_tick_*` получат номер, перенести то же на клиент. Сети не будет, а позиции трофеев мод запомнит из `native_block_entity_submit` или из клиентской копии block entity.

### 8.2 Коробка спавна

Координаты от нижнего северо-западного угла блока, в пикселях:

- x и z: от 3 до 13. Внутри рамки по рёбрам, частицы не лезут в столбы.
- y: на 0.5–1 пиксель выше верха земли диорамы (верх земли берётся из файла трофея). Для снега — 14–15.
- Частицы со столкновениями спавнить только выше формы столкновения блока. Проще сделать форму столкновения трофея только по подставке.

### 8.3 Эффекты по мобам

Частота — среднее число частиц на одну диораму. На сервере это шанс за тик: 20 тиков в секунду.

| Эффект | Где | Тип | Частота | Настройки своего типа |
|---|---|---|---|---|
| Низкий туман | Латник (кладбище), слизь (топь) | Свой `soulscraft:mist`, сероватый мягкий спрайт | 1 раз в 10 тиков (2 в секунду) | `velocity [0, 0.002, 0]`, `velocity_jitter [0.004, 0, 0.004]`, `gravity 0`, `friction 1`, `lifetime 50`, `size [0.06, 0.12]`, `alpha [0.45, 0]` |
| Души над могилой | Латник | `soul` | 1 раз в 60–80 тиков | Ванильный; `count 0`, скорость вверх 0.01–0.02 |
| Угли | Громила (камень и гравий) | `small_flame`, изредка свой `soulscraft:ember` | 1 раз в 15 тиков | Свой: `size [0.02, 0.01]`, `velocity [0, 0.01, 0]`, `lifetime 25`, `alpha [1, 0]` |
| Огонь душ | Если нужен где-то | `soul_fire_flame` | 1 раз в 15–20 тиков | Ванильный; на клиенте его же даёт `flame_particle(at, true)` |
| Снег | Сорокопут (скала со снегом) | Свой `soulscraft:snow`; `white_ash` как запасной | 1 раз в 5 тиков (4 в секунду) | `velocity [0, -0.012, 0]`, `velocity_jitter [0.003, 0, 0.003]`, `gravity 0`, `friction 1`, `lifetime 50`, `size [0.025, 0.02]` |
| Пузыри в воде | Удильщик | Свой `soulscraft:bubble` со спрайтом пузыря, на поверхности — `bubble_pop` | Пузырь раз в 15 тиков, лопание раз в 20 | `velocity [0, 0.01, 0]`, `lifetime 15`, `size [0.015, 0.02]` |
| Грязевые пузыри | Слизь (топь) | `bubble_pop` у самой земли, изредка `item_slime` | Лопание раз в 25 тиков, слизь раз в 80 | Ванильные |
| Споры, мошки | Ловчий (лес) | `crimson_spore` или `warped_spore`; свой `soulscraft:mote` | 1 раз в 8 тиков | Свой: `velocity_jitter [0.003, 0.002, 0.003]`, `lifetime 60`, `size [0.012, 0.012]` |
| Светлячки | Ловчий, топь | Ванильный `firefly` | Не чаще раза в 200 тиков | Светится сам, но улетает на блоки и живёт 10–15 секунд. Свой тип в коробке останется, но светиться не будет |
| Песок | Арбалетчик | Ничего или `falling_dust` с состоянием `minecraft:sand` | Раз в 40 тиков | — |

Чего не брать:

- `bubble` и `bubble_column_up`: вода в диораме нарисована, а не настоящая, и такие частицы удаляются в первый же тик.
- `spore_blossom_air`: живёт 25–50 секунд, улетает и тратит общий предел 1000.
- `campfire_cosy_smoke`: втрое крупнее и видна дальше 32 блоков.
- `lava`: прыгает и вылетает из рамки.

Живых частиц на диораму при такой частоте около 5–10. На комнату из 20 диорам выйдет сотни, против предела 16384.

### 8.4 Анимировать ли позу

- Да, если замер стоимости кадра (09-trophies, «Что проверить», п. 3) это позволит. Медленный цикл покоя: дыхание на 0.5–1 пиксель фигурки, лёгкое покачивание головы. Период 3–5 секунд. Время берётся из `draw.game_time + draw.partial`. Сдвиг фазы — от хэша `pos`, чтобы ряд трофеев не дышал в такт.
- У анимированных трофеев `keep()` не вызывать. Он замораживает позу до смены данных.
- `keep()` вызывать у статичных вариантов (бюст на щите, постамент в позе атаки) и вообще у трофея без анимации. Поза меняется по правому клику, это смена данных block entity, и рисунок перестроится сам.
- Мерцание углей и огоньков в диораме рисовать в block entity: `draw.light = 0xF0F0` и меняющийся `tint` по `game_time`. JSON-модель подставки так не умеет: её грани `light_emission` горят ровно.

### 8.5 Свет

- Трофей по умолчанию — свет 0. Чтобы фигурка не была тёмной, шаблон должен пропускать свет: не загораживающий или с `"occludes": false`.
- Если свет нужен, то не больше 3, как у магмы. Это лёгкое свечение без освещения комнаты. Но `light` действует на весь блок сразу, поэтому разный свет у разных сцен — это разные блоки. Так и сделано: у каждого моба свой блок `<моб>_trophy`.
- Мигающий тёплый или холодный свет — `native_visuals`, по огню на ближайшие диорамы. Это не больше 8 огней на мод, и он не идёт в игровой свет.

## 9. Неизвестные и что проверить

1. Доходят ли частицы из `send_particles` до окна в одиночке. Встроенный сервер работает на том же хабе гостей, что LAN (`client/game/integrated.rs:1-10`, `lan_particles.rs:634-676`), но в игре это никто не проверял.
2. Ссылка на ванильный спрайт в своём `particles/*.json` (`"textures": ["minecraft:bubble"]`) не проверена. Если не сработает — свой спрайт пузыря.
3. Поведение частицы со столкновениями, рождённой внутри формы столкновения блока.
4. Когда `add_particle`, `client_tick_*`, `draw_text` и `spin` получат номера. Проверять по `native-hooks.json` нового коммита.
5. Стоимость 20 анимированных диорам за кадр против 20 сохранённых через `keep`.

Что выбрано для диорам (свет 1–5, свои типы частиц, их размер и частота) — [09-trophies.md](../design/09-trophies.md). Размеры частиц там крупнее, чем в таблице 8.3: при размере 0,01 блока искра и снежинка тоньше пикселя, и с 3 блоков их не видно.

## 10. Проверка итерации 3 (2026-11-13)

Код третьей итерации опирается на эти факты; каждый перепроверен по исходникам `7e4e421` (пути от `crates/horizon-client/src/`).

- `send_particles` из тика уровня: хук тика block entity получает только `pos` и сам block entity, без игры [И] `game/native_hooks.rs:3536`, поэтому тик диорамы только записывает место, а частицы шлёт тик уровня (`level_tick_post`, во время него уровень этого измерения стоит на месте [И] `game/levels.rs:559-561`) через `Game::with_level` [И] `game.rs:4716-4719` и `GameLevel::native_send_particles` [И] `game/native_hooks.rs:9928-9963`: проверка `native_authoritative`, проверка типа, очередь `native_particles`. Это та же функция, что за стабильным `LevelWriteHost::send_particles` [И] `game/mod_api_host.rs:254-264`. `Game::native_send_particles_in_place` делает то же, но она ожидающая (`@API:host_bridge@`) [И] `game/native_host_bridge.rs:69-90` — её мод не берёт.
- Свой тип частицы `ParticleOptions::named("soulscraft:mist")` — [И] `horizon-client-render/src/particles.rs:87-92`, импорт `horizon_client::particles::ParticleOptions` [И] `game/native_hooks.rs:10412`.
- `BlockEntityDraw` несёт `partial`, `game_time`, `light`; `keep()` — метод API 94 [И] `game/native_block_entity_draw.rs:44-56, 210`. Состояние блока на клиенте мод читает `native_block_property(pos, key)` из мира клиента [И] `game/native_hooks.rs:11156-11163`.
- Свет диорамы: `"light"` в `properties` блока, ключ проверяется `deny_unknown_fields` (`mod/sync.ps1` `Assert-BlockSchema`); в фактах состояния это `emission` [И] `horizon-items/src/blocks.rs:35-37` — его сверяет самотест `trophy_blocks`.
- Установка: `native_state_for_placement` (API 76) вызывается из `before_state_for_placement` на каждом `BlockItem.place` авторитетного сервера, без проверки `mods()` [И] `game.rs:1659-1669`; ответ — состояние того же блока [И] `game/native_hooks.rs:1754-1793`. Поля `PlacementContext` (`yaw`, `face`, …) [И] `horizon-world/src/level/place.rs:55-85`.
- Голова на стену: `wall_block` движок принимает только у шаблонов табличек [И] `horizon-mods/src/content.rs:1182-1190`; предмет блока на шаблоне черепа скопировал бы ванильный `wallBlock` [И] `mod_content.rs:1385-1394`. - Текст таблички: `native_draw_text` — всё ещё `@API:draw_text@` [И] `game/native_block_entity_draw.rs:582`.

Что видно в игре — `prototypes/p7-rewards.md` и `prototypes/evidence/round10/`.
